# Boss Enemy 보행면 이탈 시 은신·재등장 복구 계획

작성일: 2026-10-08 (한국 시간)  
상태: 설계 제안. 이번 단계에서는 코드·Blueprint·레벨·설정을 변경하지 않는다.

## 1. 목표와 적용 범위

보스가 순간이동한 뒤 실제 위치가 유효한 갑판 보행면 위가 아니라면 다시 은신하고 안전한 위치에 재등장한다. 피격·Dash·Strafe 때문에 이탈한 경우도 동일한 복구 요청 경로로 처리할 수 있도록 설계한다.

순간이동 전에 목적지를 검증하는 예방 처리와, 이동 이후 실제 위치를 확인하는 예외 처리를 함께 적용한다. 정상 보행, 전투 스킬과 사망·보상 처리의 기존 책임은 유지한다.

이 문서의 복구는 게임플레이 상태 기반 처리이다. C++ 언어의 try/catch를 도입하는 작업이 아니다.

## 2. 현재 구현에서 확인한 사항

| 구현 | 현재 동작 | 계획상 의미 |
| --- | --- | --- |

| 같은 Task의 `RelocateHidden()` | 이동 직후 `MarkDestinationReached()`로 목적지와 Claim을 정리하고, 이후 Settle 시간을 기다린다. | 새 목적지의 Claim은 재등장 검증 완료까지 유지하는 편이 안전하다. |

확인 범위는 현재 C++와 저장된 문서이다. 실제 사용 중인 모든 Blueprint 오버라이드, 피격 몽타주, 런타임 충돌 상태는 이번 조사에서 재현·조회하지 않았다. 위 공백은 확인했지만 신고된 낙하의 단일 원인이라고 확정하지 않는다. 기존 AI 문서의 waypoint 기반 설명보다 현재 `FDeckWalkLocation` 구현을 기준으로 설계한다.

## 4. 보행면 판정과 감지 시점

### 4.1 실제 안전 배치 판정

다음 조건을 함께 평가한다.

1. 보스 생존, 유효한 HostShip, 보행면 Ready, 현재 Revision.
2. 캡슐 중심이 아닌 실제 발 위치와 새 바닥 probe 결과. 이전 `CurrentFloor`만 재사용하지 않는다.
3. 현재 HostShip의 등록된 보행면에 해당하는 바닥·Surface인지 확인. 난간·천장·다른 배·바다를 갑판으로 인정하지 않는다.
4. 발 위치와 바닥의 높이 차이, 캡슐 공간, 현재 장애물·다른 Pawn·Claim.
5. 외곽·구멍에 걸치지 않는 안전 여유. 실제 캡슐 크기를 사용하고 경계 근처에서는 보조 지지 샘플로 보강한다. 계단·경사면에 대한 허용 기준은 별도로 둔다.
6. 로컬 위치를 현재 함선 transform으로 해석했을 때와 실제 캡슐 위치의 오차.

`ResolveActorOnDeck()` 성공만으로 안전을 확정하지 않는다. 이 함수는 발에서 아래로 최대 65 cm의 probe 및 주변 노드 허용 범위를 가진다. 반대로 Falling 한 프레임만으로 이탈을 확정하지 않는다. 결과는 `Safe`, `TransientAirborne`, `Unsupported`, `RailOrObstacle`, `Blocked`, `AreaNotReady`, `WrongHost`처럼 원인을 구분한다.

### 4.2 감지 시점

- Vanish / VanishV2 / ChainVanish / ChainSlashDash의 공통 순간이동 직후, 재등장 직전, 재등장 후 첫 실제 이동 업데이트.
- Dash 종료·중단, Strafe 종료, 피격·강제 이동 종료.
- 생존 보스에 대한 낮은 빈도의 서버 감시를 보조로 사용한다. 전투 상태에서만 검사하면 타깃이 없는 이탈을 놓칠 수 있으므로 활성 보스 전체를 대상으로 한다.
- 순간이동 후 명백한 잘못된 배치는 즉시 복구한다. 일반 공중 상태는 짧은 유예 및 연속 실패 기준을 사용한다.
- 스폰·Intro·룸 복원·보행면 재생성은 별도 초기화 상태로 다룬다. 아직 Ready가 아닌 상태를 곧바로 낙하로 판단하지 않는다.
- 물·킬 볼륨·KillZ보다 먼저 복구할 수 있는 높이·위험 기준을 확인한다. 이미 사망한 뒤 되살리는 처리는 하지 않는다.

## 5. 복구 상태 흐름

```text
정상
  → 이탈 의심
  → 이탈 확정 / 복구 요청 병합
  → 전투 이동 중단 및 은신
  → 안전 목적지 선택·예약
  → 현재 함선 좌표로 재해석·배치 검사
  → 숨긴 상태로 이동
  → 새 바닥 검증·정착
  → 충돌·Base·MovementMode 복원 및 재검증
  → 재등장
  → 현재 전투 상태 재평가
```

정상 Vanish의 숨긴 이동 중 실패했다면 숨김을 유지하고 목적지를 다시 고른다. 아직 나타나지 않았으므로 출발 이펙트를 반복할 필요가 없다. 이미 나타난 뒤 이탈을 감지한 경우에는 사용자가 요청한 대로 다시 은신·재등장한다.

### 실행 순서의 핵심

1. 복구 세대 번호와 HostShip을 캡처하고 중복 요청을 병합한다.
2. 실패한 공격의 이동 Task·타이머·히트 윈도우·Dash 피해 볼륨·Root Motion Source·예약을 정리한다. 전체 ASC의 Ability나 Effect를 일괄 삭제하지 않는다.
3. 기존 Ability 종료 callback이 복구 목적지·숨김 상태를 덮어쓰지 못하도록 소유권과 세대를 검사한다. 전환 중에는 이전 `OnDestroy()`가 잘못된 위치에서 가시성을 복원하지 않게 한다.
4. 숨김과 이동 정지 상태를 전송한 뒤 이동한다. 복구 중 기존 전투가 다시 활성화되지 않도록 전용 상태를 두고, BT의 범위 abort가 복구를 중단하지 않게 한다.
5. 정착 중 이동 비활성화로 Base 추종이 멈출 수 있는지 확인한다. 필요하면 숨긴 상태에서 목적지 로컬 좌표를 현재 배 transform으로 다시 맞춘다. 오래된 월드 transform을 기다렸다가 그대로 사용하지 않는다.
6. 숨김으로 충돌이 꺼져 있어도 명시적인 캡슐 배치 질의를 수행한다. 충돌을 복원한 상태에서도 숨김을 유지한 채 새 floor check를 실행한다.
7. 검증 성공 후에만 Walking·유효 Base·가시성을 확정하고 Arrival cue를 발생시킨다. Claim은 이 시점까지 유지한다.
8. 현재 타깃, Stun/Frozen, 전투 상태를 다시 평가한다. 복구 직후 자동 추가 공격을 하지 않는다. Stun이 남아 있으면 갑판에 복귀한 상태로 남은 Stun을 유지한다.

숨김 진입·이동·충돌 복원·재등장 단계는 단순히 `ForceNetUpdate()`를 여러 번 호출했다고 클라이언트에서 순서가 보장되는 것으로 간주하지 않는다. 기존 숨김·이동 복제를 사용하고, 지연·패킷 손실에서 순서가 깨지면 복구 세대/단계 정보를 보강한다. 렌더링은 클라이언트, 최종 위치·복구 성공 판단은 서버 책임이다.

## 6. 복구 목적지 선택

일반 공격 선택기와 별도의 복구 선택 정책을 둔다. 현재 보스의 갑판 해석이나 Player 타깃을 필수 입력으로 요구하지 않는다.

### 후보 우선순위

1. 마지막으로 실제 안전 접지가 확정된 로컬 위치·Surface 주변의 안쪽 후보.
2. 같은 Surface·허용 전투 영역의 복구용 authored anchor 주변 후보.
3. 기존 보스 스폰 anchor를 현재 보행면에서 다시 해석한 후보.
4. 명시적으로 허용된 다른 Surface의 복구 anchor. 기본은 같은 Surface이며 층 변경은 설정으로 허용한다.

매 후보에서 바닥·Revision·영역·외곽 여유·캡슐·현재 장애물·Pawn·Claim을 검증하고 예약한다. 실패한 후보는 같은 복구 시도에서 제외한다. 플레이어 앞뒤 관계·최소 이동 거리·공격 사거리 조건은 복구의 필수 조건이 아니다. 플레이어와 겹치지 않는 조건은 유지한다.

마지막 안전 위치는 지속적으로 확인된 실제 접지에서만 갱신한다. `PreviousLocation`은 목적지 변경 때 갱신되는 값이므로 안전 위치 이력으로 그대로 사용하지 않는다. `TrySetDestinationLocation()`도 현재 바닥 해석으로 이를 갱신하므로 복구 시 기존 안전 이력을 보존해야 한다.

Revision이 바뀌면 옛 NodeIndex를 재사용하지 않고 저장된 로컬 좌표·Surface/anchor에서 새 핸들을 구한다. 이탈 위치에서 목적지까지 보행 경로가 없다는 이유로 복구를 거절하지 않되, 목적지 자체가 허용된 전투 구역에 속하는지는 확인한다.

## 7. 실패·중단 정책

| 상황 | 처리 |
| --- | --- |
| 이동 전 후보가 점유·차단됨 | 예약을 정리하고 다른 후보로 제한 재시도한다. |
| 위치 설정 실패 또는 실제 배치 불일치 | 성공 처리하지 않고 숨김 상태에서 다른 후보를 선택한다. |
| 정착·재등장 검사 실패 | Claim을 해제하고 새 후보로 복구를 계속한다. 안전하지 않은 위치에서 `FinishHiddenRelocation()`하지 않는다. |
| Player 타깃 사망·소실 | 공격은 중단하되 복구는 타깃 없이 완료한다. |
| 보스 사망 | 모든 복구를 중단하고 기존 사망 흐름을 실행한다. 늦은 callback으로 숨김·이동·체력을 되돌리지 않는다. |
| 함선 파괴·Encounter 종료·Host 변경 | 기존 Encounter 정리 정책이 우선한다. 다른 배로 임의 이동하지 않는다. |
| 보행면 일시 NotReady | 제한 시간 동안 숨김·공격 중지 상태로 대기하고 재해석한다. |
| 모든 안전 후보 소진·총 복구 시간 초과 | 최종 안전 anchor를 다시 검증한다. 이것도 실패하면 Encounter 실패 경로로 종료하는 안을 권장한다. 보상 상자는 Defeated로 처리하지 않으며 숨긴 보스를 무한 유지하지 않는다. |

총 복구 시간·시도 횟수 상한을 두고 시도별 원인을 기록한다. `3회`, 총 `2~3초`, 감시 `0.1~0.2초`, 일시 공중 유예 `0.15~0.3초`는 시작 튜닝 후보이며 확정값이 아니다. 기존 hidden lead/settle 시간을 검토하고 현재 이동·복제 빈도에 맞춰 정한다. 복구 억제 시간 중 다시 위험한 위치가 되면 요청을 버리지 않고 진행 중 복구에 합친다.

복구 중 HP·일반 스킬 쿨다운·보상 상태를 초기화하지 않는다. 일반 Vanish가 이미 소비한 쿨다운은 유지하며 복구 자체는 추가로 소비하지 않는다. 숨김으로 피해 판정이 달라지는 기존 정책을 확인하고, 재시도 상한으로 무한 회피를 방지한다.

## 8. 단계별 구현 계획

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1. 재현·계측 | 순간이동 전후, 첫 floor check, 숨김·충돌·Base 전환, 함선 로컬 오차를 기록한다. | 잘못된 후보, 이동 중 함선 변위, 재등장 이후 피격을 구분한다. |
| 2. 공통 판정 | 실제 배치 검증과 실패 사유를 구현한다. 마지막 안전 위치 갱신 정책을 만든다. | 바다·난간·다른 층을 안전 접지로 잘못 인정하지 않는다. |
| 3. 기존 Task 보강 | 이동 호출 결과, 이동 후·Reveal 전 검증, Claim 유지, 실패 정리/소유권을 수정한다. | 정상 전투용 Vanish도 안전 검증을 통과한 위치에서만 나타난다. |
| 4. 복구 실행 | 서버 복구 관리자·전용 GA·타깃 없는 목적지 선택·제한 재시도를 추가한다. | 이미 배 밖인 보스도 안전하게 재등장한다. |
| 5. 전체 이동 연결 | Vanish 변형·Dash·Strafe·피격/강제 이동·보조 감시를 연결한다. | 모든 이탈 요청이 단일 복구 세대에 병합된다. |
| 6. 에디터 구성 | 실제 보스 클래스에 GA와 설정을 부여하고 Surface별 복구 anchor를 확인한다. | 최종 SpawnPlan이 쓰는 보스 변형에도 설정이 적용된다. |
| 7. 회귀·네트워크 | 아래 테스트를 수행하고 튜닝·진단 문서를 갱신한다. | 사망·전투·복제·보상 계약이 유지된다. |

예상 코드 검토 대상: `ShipBossEnemy.{h,cpp}`, `BossDeckPointSelector.{h,cpp}`, `AbilityTask_BossVanishRelocation.{h,cpp}`, `GA_BossVanish.cpp`, `GA_BossChainVanish.cpp`, `GA_BossChainSlashDash.cpp`, Dash/Strafe 실행부, `DeckWalkAreaComponent.{h,cpp}`, 신규 복구 관리자/GA, 필요한 태그 및 테스트. 어떤 전투 GA가 배치 후 검증을 우회하는지 먼저 목록화한다.

## 9. 검증 계획과 수용 기준

자동화는 안전 판정·재시도·수명 경합 등 결함 위험이 있는 동작을 중심으로 추가하고 기존 BossMVP/BossDeath/BossHurtbox/BossStatus 테스트를 회귀 실행한다.

- 갑판 안쪽 정상 순간이동, 외곽·구멍·난간·천장·장애물·다른 Pawn의 잘못된 종점.
- 목표 선택 후 배 회전·상하 운동, 정착 중 이동, Revision 변경, 목적지 Claim 경쟁.
- 보스가 이미 Falling이거나 갑판 아래에 있을 때 타깃 없는 복구.
- 정상 Vanish 쿨다운 중, Busy/Attacking/Damaged/Stun 중 복구. 남은 상태·쿨다운 유지.
- 각 Vanish 변형의 최초·중간·마지막 이동 실패와 Dash/Strafe 종료 후 이탈.
- 복구 중 사망·함선 파괴·타깃 소실·룸 복원·늦은 Task callback·중복 요청.
- 모든 후보 차단 시 제한된 종료와 Encounter 보상 미지급.
- Standalone, Listen Server와 원격 클라이언트, Dedicated Server와 2 Clients. 지연·손실 환경, 늦은 관련성/접속에서 가시성·캡슐·무기·Arrival cue를 확인한다.

수용 기준: 안전 검사 성공 전 공격과 가시성이 복원되지 않음, 단일 복구만 실행, 제한 시도 내 정상 복귀 또는 명시적 실패 종료, 안전 바닥·올바른 HostShip Base 확인, HP/쿨다운/Stun 유지, 사망 callback이 복구를 무효화, 정상 전투 이동 및 보상 동작 회귀 없음.
