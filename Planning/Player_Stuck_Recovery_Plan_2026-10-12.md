# Player 끼임 감지·탈출 구현 계획 및 적용 기록

작성일: 2026-10-12. 기준 엔진: 프로젝트의 UE 5.7.
요구사항: [공유 대화의 개선 설계 v2](https://chatgpt.com/share/6acc36d6-e320-83e8-88f2-a63121785492?no_universal_links=1).

## 접근 타당성

이벤트로 감시를 시작하고, 이동 정체와 충돌 증거가 지속될 때 탈출을 허용하는 접근은 현재 프로젝트에 적용 가능하다. `ABasePlayer`의 Enhanced Input, 서버 이동 입력 전달, `USWCharacterMovementComponent`, GAS 피격/구르기 Ability를 이용한다. 공유 문서의 UE 5.8 표기는 실제 프로젝트의 UE 5.7에 맞추었다.

MovementMode 변경, 몽타주 실행, 장시간 대기는 **감시 원인**이다. 그 자체가 끼임이라는 판정 근거는 아니다. 정상적인 대기·벽 밀기·착지·스턴을 분리해야 한다. 피격 원인의 재현과 에셋 수정 없이 원래 끼임 자체를 제거했다고 주장하지 않는다.

## 책임과 구현 순서

| 순서 | 담당 | 적용 내용 |
| --- | --- | --- |
| 1 | `StuckRecoveryTypes` | 에디터 설정과 상태 열거형 정의 |
| 2 | `StuckRecoveryCollision` | 캡슐 침투·수평 8방향 폐쇄 검사, 목적지 점유·경로·착지 검사 |
| 3 | `UStuckRecoveryComponent` | 서버 상태 머신, 감시 토큰, Fallback, 홀드 시간 검증, 복구 실행 |
| 4 | `UAbilityTask_MonitorStuckRecovery` | GA 실행마다 독립 감시 등록, 종료·취소·중단의 대칭 해제 |
| 5 | `ABasePlayer` 연결 | 기본 컴포넌트 생성, 기존 입력 경로에서 이동 의도 전달 |
| 6 | `UStuckRecoveryInputComponent` | 로컬 탈출 입력 바인딩, 누름·해제 전달, 안내 UI 수명 |
| 7 | `UStuckRecoveryWidget` | 안내 문구, 서버 기준 진행률, 실패 안내, 교체 가능한 레이아웃 |
| 8 | 빌드·수동 확인 안내 | 자동화 테스트는 요청대로 추가·실행하지 않음 |

구현 단계 1~7은 코드에 적용했다. 실제 설정 및 수동 확인 절차는 [사용 가이드](../docs/Player_Stuck_Recovery_Editor_Guide.md)를 따른다.

## 현재 프로젝트에 맞춘 선택

- 공통 GA 상속 계층을 바꾸는 대신 AbilityTask를 사용했다. 피격과 구르기는 서로 다른 기존 기반 클래스를 그대로 사용하면서 같은 감시 수명을 공유한다. 다른 GA도 같은 Task를 호출할 수 있다.
- MovementMode는 Character의 기존 delegate를 구독한다. 몽타주는 샘플 주기마다 재생 상태를 관찰한다. 다른 코드의 몽타주 종료 delegate를 덮어쓰지 않는다.
- `DoMove`, `StopMoveInput`, 기존 `Server_SetMoveInput`에서 입력 의도를 기록한다. 이동 의도용 별도 RPC는 추가하지 않았다.
- `UInputTriggerHold`와 컴포넌트 타이머를 중복 사용하지 않는다. Boolean IA의 시작·해제를 받고 **서버가 실제 경과 시간을 계산**한다. 키 직접 설정 방식도 제공한다. 두 방식 모두 기본 홀드 시간은 3초다.
- 안내 위젯의 기본 구현을 제공하므로 Widget Blueprint 제작은 선택사항이다. 새 입력/위젯 바이너리 에셋은 필수로 생성하지 않았다. 키 선택은 요청대로 에디터에 남겼다.
- 함선의 이동·회전이 플레이어의 정상 이동으로 오인되지 않도록, 현재 MovementBase가 유지되면 이전 위치를 그 베이스의 현재 좌표로 변환해 이동량을 계산한다.

## 판정 및 복구 정책

서버에서만 충돌을 검사한다. 감시 중 캡슐이 초당 30cm 이하로 이동하고, 축소 캡슐의 blocking 침투 또는 수평 8방향 이동 불능이 0.75초 이상 유지되면 확정한다. `MOVE_None`이면서 이동 입력이 있는 경우도 후보로 본다. 스턴·수영·사망·컨트롤러 입력 무시·탑승은 먼저 제외한다. 의도적인 별도 이동 잠금은 서버의 `SetDetectionSuspended` 또는 SuppressionTags로 알려준다.

이벤트가 없으면 입력과 이동 모두 없는 5초 후 정밀 검사를 시작한다. 정상 대기는 기본 1초마다만 충돌 검사하며, 의심 상태가 생기면 0.1초 간격으로 확정 여부를 평가한다. 입력 또는 낙하 의도에도 이동하지 못하면 별도 0.75초 Fallback이 활성화된다. 긴 프레임 하나를 여러 관측으로 간주하지 않는다.

탈출은 yaw 기준 전방 150cm + 월드 상단 100cm부터 최대 8개 후보를 검사한다. 점유 가능한 캡슐 공간, 250cm 이내의 걸을 수 있는 지면, 직선 또는 위로 이동한 뒤 전방으로 이동하는 경로가 필요하다. 시작점이 이미 침투한 경우에만 역방향 sweep의 마지막 막힌 구간을 최대 75cm까지 허용하며, 원래 겹친 충돌체인지와 새로운 장애물 부재를 추가로 검사한다. 일반 벽을 뚫는 이동은 허용하지 않는다.

목적지가 확보되면 감시 중인 취소 가능한 GA를 취소하고, GAS 몽타주 정지와 Root Motion·누적 힘 정리를 수행한다. 취소 훅 이후 목적지를 다시 검사하고 서버가 위치를 복구한다. `MOVE_Falling`으로 자연 착지시키며 기존 Character 이동 복제로 위치를 전파한다. 성공 후 2초 쿨다운, 실패 후 키 해제를 요구한다. 취소 불가능한 감시 GA가 남아 있으면 복구를 거절한다.

## 검증 범위

2026-10-12 최종 `ArtisticSW2026Editor / Win64 / Development` 빌드와 UnrealHeaderTool 처리가 성공했다. 변경 코드의 공백 오류 검사도 통과했다. 자동화 테스트는 추가하거나 실행하지 않았다. 실제 피격 재현, 키 설정, 지형별 임계값 조정, listen/dedicated server의 이동 보정, 함선 위 사례는 에디터 수동 확인 대상이다.

완벽한 자동 판별은 보장하지 않는다. 깊은 침투, 복잡한 충돌 메시, 물속, 이동 지형, 게임별 컷신·이동 잠금 규칙은 별도 조정이 필요하다. 목적지의 현재 충돌 및 착지 가능성을 검사하지만, 향후 움직일 장애물이나 게임별 피해 볼륨까지 예측하지 않는다. 입력 누름/해제 메시지와 서버 시간을 검증하는 구조이며 물리 키가 실제로 눌렸음을 증명하는 안티치트 기능은 아니다.
