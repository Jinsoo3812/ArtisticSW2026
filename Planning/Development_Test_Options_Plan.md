# 테스트 옵션 분리 및 캠페인 건너뛰기 구현 계획

상태: 사용자 결정 반영 및 C++ 구현 완료. 정적 검증 수행. 빌드/런타임 검증 미실행. 사용법과 최종 대상 목록은 docs/Development_Test_Options.md 참조.

## 확정된 요구사항

- BP_Player의 테스트 동작을 별도 개발 테스트 설정으로 분리한다.
- 배 강화 재료 검사와 소모를 함께 우회한다. 노드 선행 조건과 이미 강화된 상태는 유지한다.
- 제작은 레시피 아이템 보유 조건과 제작 재료 검사/소모를 모두 우회한다(사용자 확정).
- 플레이어 스킬 사용 재료와 쿨타임을 우회한다.
- 캠페인 이동 시 접속한 모든 플레이어에게 누적 필수 보상을 지급하고 현재 방 진행에 반영한다(사용자 확정).
- 배 조종 중 C 카메라 변경은 테스트 세션에서만 허용한다.
- 빌드, 에디터 실행, 런타임 테스트 없이 소스 정적 검증을 수행한다.

## 확인한 기존 구조

| 영역 | 기존 진입점 | 필요한 변경 |
| --- | --- | --- |
| 테스트 권한 | SW.DevTest.Session, USWDevTestInputComponent | 호스트 권한과 서버 검증 재사용, 개별 옵션 명령 추가 |
| 방 단위 상태 | USWRoomProgressSubsystem | 테스트 옵션을 플레이어 BP와 분리하고 승인된 재시작에 한해 전달 |
| 클라이언트 공유 상태 | ASWRoomReadyState | 옵션 복제와 UI 갱신 신호 제공 |
| 배 강화 | ABasePlayer::ApplyShipUpgradeTestFlags, UShipUpgradeComponent | BP 기본값 대신 공통 옵션 사용, UI/서버 비용 판단 일치 |
| 제작 | UCraftingComponent | 목록, 상세, 최대 수량, 서버 검사, 실제 비용 계산 모두 동일 정책 적용 |
| 스킬 | ABasePlayer, UPlayerSkillComponent, UPlayerSkillGameplayAbility | 재료 우회 및 GAS 쿨타임 검사/적용 우회, 퀵슬롯 표시 갱신 |
| 물폭탄 발사 | ACannon | 일반 포격과 물폭탄의 발사 간격을 구분하여 스킬 쿨타임 정책 적용 |
| 카메라 | AShip::ToggleHelmCamera, SetHelmFirstPersonCameraEnabled | 공통 테스트 상태 검사, 종료 시 기본 시점 복귀 |
| 캠페인 | UStoryFacadeSubsystem, EStoryNode | 기존 노드와 명시적 선행 노드 집합 사용 |
| 재시작/복원 | UClassFeatureRoomProgressSubsystem, AMultiGameMode | 로딩 확인, 서버 재시작, 방 진행 및 안전 배치 복원 절차 확장 |

기존 최종전 테스트는 ActivateDevelopmentFinalBattle로 최종 퀘스트만 열며, 이전 캠페인 보상이나 누적 노드를 만들지 않는다. 새 건너뛰기는 이 동작을 그대로 재사용할 수 없다.
기존 테스트 세션은 월드에 귀속되고 일부 최종전 전환에서 해제된다. 새 옵션을 전역 CVar에만 보관하면 PIE 월드와 서버/클라이언트가 섞일 수 있으므로, 명령은 현재 월드의 서버 상태를 바꾸는 방식으로 구현한다.

## 설정과 명령 설계

기존 SW.DevTest.Session 0|1을 전체 스위치로 유지한다. 기본값은 꺼짐이며 기존 개발 빌드 정책(Shipping/Test 비활성)을 따른다.

제안 명령:

- SW.DevTest.ShipUpgradeFree 0|1
- SW.DevTest.CraftingFree 0|1
- SW.DevTest.SkillFree 0|1
- SW.DevTest.SkillNoCooldown 0|1
- SW.DevTest.Status
- SW.DevTest.Campaign.List
- SW.DevTest.Campaign.Skip <대상 이름>

카메라는 Session 상태를 따른다. 개별 옵션은 Session이 켜져 있을 때만 효력이 있다. 옵션 변경은 호스트가 요청하고 서버가 검증한 후 클라이언트에 복제한다.
테스트 옵션은 게임의 영구 스킬 해금 기록과 분리한다. 캠페인 건너뛰기로 실제 얻은 스킬 해금은 정상 진행 기록에 남긴다.
기존 BP 테스트 변수는 참조 호환성을 확인한 후 사용 경로와 편집 노출을 제거한다. 시작 아이템 목록 역시 별도 테스트 설정으로 이전할 대상으로 조사한다. 바이너리 BP 기본값을 소스 조사만으로 완전히 확인하거나 자동 이전했다고 간주하지 않는다.

## 캠페인 이동 대상 초안

각 전투 대상은 해당 보스를 아직 처치하지 않은 시점이다. 완료한 보스는 다시 출현시키지 않는다.

| 대상 | 도달 상태 | 누적 필수 아이템 초안 | 영구 해금 |
| --- | --- | --- | --- |
| MiddleBoss1 | 첫 출항 및 정찰 수락 | 없음 | 없음 |
| MiddleBoss2 | 중간보스 1 처치, 보급로 순찰 수락 | 명량 침공 지도, 암호 해독서 | 해류 발생기 |
| MiddleBoss3 | 중간보스 2 처치, 해독 퀘스트와 원군 저지 수락 | 위 아이템 + 일본군 암호, 해독된 암호 | 위 스킬 + 물폭탄 |
| FinalBoss | 중간보스 3 처치, 울돌목 전투 수락 | 위 아이템 + 일본군 공습 정보 | 위 스킬 + 포탄세례 |
| Ending | 최종보스 처치 및 엔딩 대화 완료 | 위 누적 필수 아이템 | 위 누적 스킬 |

암호 해독서는 사진에서 독립 분기이므로, 순서상 앞선 enum 값을 모두 완료하는 방식은 사용하지 않는다. 개별 트리거 이동을 선택하면 분기별 선행 노드 집합과 보상표를 확장한다.
필수 아이템은 기존 Item.Quest.* 태그를 사용한다. 무작위 일반 전리품은 확정 보상으로 취급하지 않는다. 보상 수량은 대상별 필수 수량을 기준으로 부족분을 지급하며 같은 대상 반복 실행으로 중복 지급하지 않도록 처리한다.
원군 저지 진행 시 재료를 소모하는 일반 제작 흐름과 달리, 테스트 건너뛰기는 요청한 누적 보상 정책에 따라 선행 필수 아이템도 보존하는 설계다.

## 안전한 이동 처리

1. 대상 이름, 테스트 세션, 호스트 권한, 현재 복원 세대, 방 준비 상태와 진행 방향을 검증한다.
2. 저장/귀환/재시작/게임오버 전환 중이거나 플레이어 상태가 불완전하면 명확한 사유와 함께 거절한다.
3. 접속 플레이어 전체, 필수 아이템 정의, 인벤토리 수용 가능 여부, 도착 지점과 배 복원 조건을 먼저 확인한다.
4. 상자/인벤토리 커서와 승선/대포 조작을 기존 정리 절차로 종료한다.
5. 기존 방 진행을 백업하고, 대상 스토리·플레이어 보상·해금 결과를 임시 데이터에 준비한다. 이 시점에 기존 월드의 스토리 이벤트를 미리 실행하지 않는다.
6. 모든 클라이언트의 로딩 화면 준비 확인 후 대상 상태를 방 복원 데이터에 반영하고 서버 재시작을 요청한다.
7. 재시작 요청 실패, 준비 시간 초과, 전환 중 참가자 변경은 취소/복구 경로로 처리한다. 일부 플레이어에게만 보상 지급된 상태를 남기지 않는다.
8. 새 월드에서 스토리, 인벤토리, 영구 스킬, 배를 복원한다. 기존 보스 스토리 게이트가 대상 시점의 출현 여부를 결정한다.
9. 모든 플레이어와 월드 준비가 확인된 후 조작을 풀고 성공 결과를 표시한다. 최종전은 기존 최종전 진입 위치 및 함대 준비 조건을 존중한다.

현재 방 반영과 디스크 저장은 구분한다. 기본 설계는 현재 방 복원 기록에 반영하고 기존 정상 저장 경로에서 디스크에 저장하는 방식이다.
인벤토리가 부족하면 전체 요청을 거절하고 필요한 공간을 알린다. 아이템을 바닥에 떨어뜨리거나 기존 아이템을 삭제하지 않는다.

## 구현 순서

1. 공통 테스트 설정/조회와 서버 명령, 복제 경로 구현.
2. 배 강화 및 제작 비용 우회, 목록/상세 UI 일치 처리.
3. 스킬 재료/쿨타임과 임시 해금 정책, 카메라 제한 적용.
4. 캠페인 대상/보상/선행 조건 데이터와 이동 요청 구현.
5. 기존 방 전환에 준비·취소·복원 처리를 연결하고 사용 안내 작성.
6. 변경 파일별 정적 검증 및 diff/CRLF 확인.

## 검증 항목

- 선언/정의, 모듈 의존성, UHT 매크로, UObject 수명, 서버 권한 및 복제.
- 옵션 OFF에서 기존 비용/쿨타임/카메라 동작으로 복귀.
- 제작 UI의 가능 여부와 실제 서버 비용 처리 일치. 결과 수량 제한과 데이터 유효성 검사는 유지.
- 물폭탄과 배 탑승 상태에서도 플레이어 테스트 옵션 적용. 적 스킬에는 적용하지 않음.
- 캠페인 분기, 동일 대상 반복, 이미 지난 대상, 잘못된 대상, 재료 정의 누락, 인벤토리 부족.
- 로딩 준비 시간 초과/참가자 이탈/재시작 요청 실패와 롤백.
- 재시작 후 보상/해금/보스 상태와 접속 플레이어별 복원 일치.
- CRLF, 기존 인코딩, 불필요한 생성 파일 및 바이너리 변경 여부.

실제 컴파일과 멀티플레이 재시작의 런타임 검증은 사용자 요청 시 별도로 수행한다. 정적 검증만으로 실행 성공을 확정하지 않는다.

## 최종 사용자 결정과 구현 반영

- 테스트 동안 미해금 스킬도 임시 사용한다. 영구 스킬 상태와 분리한다.
- 이동 대상은 사진의 이순신 대화 직후 여섯 시점: Recon, SupplyPatrol, Decipher, Suppress, Uldolmok, Ending.
- 도달 시점까지의 좌우 분기를 모두 완료하고 전원에게 필수 보상 부족분을 지급한다.
- 위 전투 직전 대상표는 초기 설계안이며, 실제 명령은 최종 대화 시점 이름을 사용한다.
- 복원 성공 후 기존 귀환/최종 출항 경로가 디스크 저장을 수행한다. 저장 실패는 기존 경고로 안내한다.
- 시작 아이템 설정도 BP_Player에서 Project Settings의 SW Development Tests로 분리했다. 기존 BP 값 자동 이관은 에디터 미실행으로 수행하지 않았다.
