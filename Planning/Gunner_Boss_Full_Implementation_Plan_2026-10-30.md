## 2. 목표와 첫 버전 범위

갑판 위에서 거리를 유지하다가 멈춰 조준선을 보여주고 사격하는 보스를 완성한다. 플레이어는 고정된 사선을 피하거나 엄폐하고, 준비·후딜에 접근해 공격한다.

첫 버전: 단발 Hitscan, 3연사, 갑판 거리 유지, 총·애니메이션·필수 피드백, 스턴·사망·보상, 멀티플레이, 풀링·저장 복원.
추가 페이즈·새 소환 패턴·전용 그로기 게이지는 후속 작업이다. 머리 피격 스턴은 기존 Boss Status/Hurtbox를 우선 사용하며 별도 스턴 확장 계획과 구분한다.

## 4. 전투 규칙과 초기 밸런스

흐름: 표적 확인 → 거리/사선 조절 → 공격 선택 → 정지·추적 → 조준 고정 → 서버 발사 → 정지 후딜 → 이동/다음 공격.

| 항목 | 단발 | 3연사 |
|---|---|---|
| 준비 | 2.0초 | 발당 1.0초 |
| 준비에 포함된 마지막 조준 고정 | 0.6초 | 발당 0.35초 |
| Strength 피해 계수 | 1.0 | 발당 0.7 |
| 발 사이 대기 | 해당 없음 | 0.2초 |
| 마지막 발 이후 후딜 | 1.2초 | 2.5초 |
| Commit 기준 쿨다운 | 0초 | 12초 |
| 후딜 후 공통 공격 대기 | 0.6초 | 0초 |

공통 초기값: 사거리 1,600cm, 후퇴 진입 400cm, 선호 거리 700cm, 접근 진입 1,000cm, 이동 종료 목표 600~800cm, 속도 220cm/s. 현재 코드 기본값에서 시작하되 최종 체력·Strength는 플레이어 방어·회복·실제 갑판 크기에 맞춰 결정한다.

단발은 1.4초 추적+0.6초 고정 뒤 발사한다. 연사는 매 발 0.65초 추적+0.35초 고정이며 첫 준비부터 마지막 발까지 약 3.4초, 마지막 후딜까지 약 5.9초다. 프레임/타이머에 따른 실제 시각은 측정한다.

LockTime=0은 발사 직전까지 추적하는 지원 모드다. 초기 회피 검증은 양수 고정 시간으로 진행한다. 0일 때는 옆 이동 회피가 어려워질 수 있어 엄폐·회피 무적과 함께 의도적으로 조정한다.

준비·발 사이·후딜 동안 보행과 다른 공격을 막되 피해를 받는다. 일반 리액션과 스턴·넉백·사망을 구분하고, 후자는 남은 사격을 취소하는지 확인한다. Busy를 무적으로 사용하지 않는다.

## 5. 에셋 연결 순서

아래 이름은 제안명이다. 기존 에셋을 확인한 뒤 재사용하며 공유 데이터를 덮어쓰지 않는다.

| 순서 | 대상 | 설정 |
|---|---|---|
| 1 | BP_GunnerGun | BaseWeapon 자식, Vetterli Rifle 메시, 충돌·물리 끔 |
| 2 | DA_GunnerWeapons | 기존 Registry 복제, Item.EnemyWeapon.Gun → 총 BP |
| 3 | Gun_Grip | 캐릭터 손 본의 총 부착 소켓 |
| 4 | Gun_Muzzle | 캐릭터 Mesh에서 조회 가능한 총구 소켓 |
| 5 | DA_GunnerCombat | GunnerBossCombatData 기반, 공격 수치·Ray 설정 |
| 6 | BP_GunnerBoss | GunnerBossEnemy 자식, Mesh/AnimBP/Physics/스탯/DA |
| 7 | BT_GunnerCombat | 기존 Blackboard, Selector 아래 Gunner Boss Combat Task |
| 8 | 전용 BehaviorSet | 공통 Root BT 유지, Combat Subtree만 교체 |
| 9 | 테스트 함선 조우 | Boss Class, 유효 Spawn Point, DeckWalkArea 연결 |

- 총 Registry의 Granted Abilities는 비운다. Pawn에 이미 사격 GA가 있다.
- BP의 EquipWeaponOnSpawn=true, DefaultWeaponTag=Item.EnemyWeapon.Gun을 확인한다. 옛 BP 저장값이 C++ 기본값을 덮을 수 있다.
- Gun_Muzzle을 총 Static Mesh에만 만들면 현재 GetOrigin 경로가 찾지 못한다. 캐릭터 Mesh 소켓과 총구를 맞추고, 애니메이션 적용 후에도 일치하는지 확인한다.
- 빨간 선은 ABossGunAimLine을 직접 생성한다. Warning Mesh/Niagara/AimLine BP 지정은 필요 없다. 기존 BP_T1_Aimline은 참조를 확인하기 전 삭제하지 않는다.
- 준비·후딜 시간은 Combat Data가 소유한다. BT와 무기 데이터에 같은 시간을 중복 복사하지 않는다.

## 6. 실행 단계와 단계별 완료 기준

### 단계 A: 단발 전투 수직 연결

정상 갑판이 있는 테스트 함선에서 BossEncounter로 생성한다. 보스를 단독 배치하면 HostShip과 Spawn Point 초기화가 누락될 수 있으므로 정식 InitializeBoss 경로를 사용한다.

총/소켓/보스/DA/BT를 연결하고 먼저 몽타주 없이 판정과 시간을 검사한다. 단발 관찰용 테스트 설정에서 시작한 뒤 기본 연사 우선 정책으로 복귀한다.

완료: 총구에서 선이 나오고 설정 시간 후 정확히 한 번 사격한다. 명중·옆 이동 회피·엄폐가 구분되고, 후딜 동안 이동 없이 피해를 받으며 이후 정상 행동한다.

### 단계 B: 갑판 거리 유지

DeckWalkArea/Route를 재사용해 접근·후퇴·엄폐 재배치를 확인한다. 기존 Combat 이동 Task·Focus Service가 총잡이 Task와 동시에 명령하지 않도록 전용 Subtree를 정리한다.

조준 고정 방향은 갑판 로컬 공간이다. 표적 추적은 멈추지만 배 회전에 따라 월드 사선은 변한다. 이 동작을 공격 의도로 유지하고 움직이는 배에서 검사한다.

완료: 난간 밖으로 걷지 않고, 후퇴 공간이 없으면 사선 확보 시 제자리 공격한다. 실패한 경로를 무한 반복하지 않으며 배 이동/회전 중 총구·선·판정이 일치한다.

### 단계 C: 3연사와 공격 선택

기존 Burst GA의 발별 준비·고정·피해 창을 검사한다. 같은 플레이어가 서로 다른 발에는 맞을 수 있지만 한 발에서 중복 피해를 받으면 안 된다.

현재 Task는 Burst를 먼저 시도하므로 첫 공격도 연사일 수 있다. 단발 소개 후 연사로 넘어가려면 초기 쿨다운 또는 첫 공격 선택 정책을 별도 변경한다.

완료: 정확히 3발, 발 사이 후퇴 없음, 마지막 긴 후딜, 쿨다운 중 단발 사용. 준비 중 다른 플레이어로 표적이 갑자기 바뀌지 않는다.

### 단계 D: 자세·애니메이션·음향

보유 클립과 스켈레톤 호환성을 조사하고, 소총 기본/이동 자세와 in-place Aim/Fire/Recover 몽타주를 연결한다. 서버 타이머가 발사하며 AnimNotify에 추가 피해를 넣지 않는다. 섹션 루프가 공격 종료 후 남지 않도록 한다.

현재 몸 회전만으로 총신의 상하 조준이나 왼손 그립이 완성되지 않는다. 필요하면 Aim Offset/상체 레이어/왼손 IK를 추가하고 실제 Trace 방향과 시각적 총구 방향을 대조한다.

현재 직접 선 표시에는 준비음·소총 발사음·총구 섬광이 없다. 전용 원음을 확보하고 서버 확정 사격 데이터에 피드백을 연결한다. 클라이언트에서 피해 판정을 새로 실행하지 않는다. 함선 대포음을 소총 완성음으로 간주하지 않는다.

현재 추적/고정은 같은 Ray 색을 쓴다. 구분이 어렵다면 고정 단계의 색·두께·짧은 소리를 추가한다. 이는 새 표현 작업이며 이미 구현됐다고 계산하지 않는다.

완료: 총 장착·상하 조준·발사·후딜 자세가 판정과 맞고, 양쪽 화면에 필요한 피드백이 중복 없이 발생한다.

### 단계 E: 캠페인·보상·풀링·복원

실제 배치할 티어·함선·스토리 단계를 정한다. T1 파일 이름만으로 기존 중간보스를 교체하지 않는다. 테스트 조우 검증 후 정식 배치를 연결한다.

실제 등장한 보스만 경호·보스 상자·필수 보상에 등록한다. 일반 경호원이 남으면 보스 사망만으로 잠금을 해제하지 않는다. 소환을 사용하지 않을 경우 Encounter Balance Row의 다른 책임도 확인하고 설정한다.

공통 배 풀의 논리 배치가 총잡이 보스 클래스·스탯·관련 설정을 유지하는지 확인한다. 귀환/Idle 정리와 재접근에서 이전 총·표적·선·타이머가 남지 않아야 한다.

조준은 저장 재개 대상이 아닌 일시 상태다. 복원 후 예약 사격을 이어 쏘지 않고 정상 BT 판단으로 돌아가되, 체력·진행·상자 상태는 기존 저장 계약으로 보존한다.

완료: 보상 중복·유령 무기·지연 발사·영구 이동 잠금 없이 조우 초기화와 저장 복원이 구분된다.

### 단계 F: 네트워크·패키징

Standalone → 2인 Listen Server/Client → Dedicated Server → 패키지 순서로 검사한다. 서버에서 안 보이는 Mesh도 공격 중 소켓이 갱신되는지, 실제 패키지에 총/DA/몽타주가 포함되는지 확인한다.

실제 입력·피해·표시 결과로 완료 판정한다. 기존 가이드에 따라 초기에는 수동 PIE 중심으로 검증하고, 반복 결함은 필요한 회귀 테스트를 별도로 검토한다. 아래 항목은 아직 실행한 결과가 아닌 예정 검사다.

## 7. 필수 검사표

| 상황 | 기대 결과 |
|---|---|
| 단발 추적→고정→발사 | 시간 일치, 한 발의 피해 중복 0 |
| 고정 직후 옆 이동 | 기존 사선을 벗어나면 빗나감 |
| LockTime=0 / PrepareTime과 동일 | 끝까지 추적 / 처음부터 고정, 멈춤·중복 없음 |
| 난간·벽·엄폐물 | WeaponAim 첫 차단점에서 끝남 |
| 다른 플레이어가 사선 진입 | 첫 Blocking Hit에 기존 팀/피해 정책 적용 |
| 준비·후딜 중 피격 | 체력 감소, 일반 리액션으로 공격 재시작 안 함 |
| 발사 직전/연사 중 스턴·넉백·사망 | 남은 발사·선·Busy·잠금 정리 |
| 표적 사망·퇴장·함선 파괴 | 안전 취소와 정상 복귀 |
| 움직이는 배·화면 밖 보스 | 총구·고정 방향·서버 판정 유지 |
| 갑판 모서리·막힌 이동 | 추락·무한 재탐색 없음 |
| 풀 반납·다른 프로필·재접근 | 옛 보스 설정·표적·공격 ID 잔류 없음 |
| 전투 중 저장·복원 | 예약 발사 없이 체력·진행·보상 보존 |
| 2인·늦은 참가·지연/손실 | 단계 표시 복구, 피해는 서버만 결정 |
| 패키징 실행 | 에셋 로드·선·총·몽타주 정상 |

문제 기록에 공격 ID, 발 순번, 서버 시각, 표적, Trace 시작/끝/Hit, HostShip을 포함한다. 검증에 필요한 진단만 켜고 상시 프레임 로그를 늘리지 않는다.
