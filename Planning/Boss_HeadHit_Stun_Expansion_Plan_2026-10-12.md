# 보스 전투 GA 실행 중 머리 피격 기절 및 피격 범위 확대 계획

작성일: 2026-10-12

상태: 소스와 기존 문서에 근거한 구현 계획. 게임 코드와 에셋은 수정하지 않았다. 실제 Blueprint 기본값, PhysicsAsset 치수와 PIE 동작은 구현 시작 시 확인한다.

## 1. 목표와 적용 규칙

보스가 전투 GA를 실행하는 동안 머리에 직접 피해를 받으면, 현재 전투 GA를 취소하고 기존 기절 상태로 전환한다. Samurai의 단발 DashSlash와 연속 ChainSlashDash가 핵심 검증 대상이다.

| 상황 | 계획된 동작 |
|---|---|
| 기본 공격의 준비·공격·후딜 중 머리 피격 | 해당 전투 GA 취소 후 기절 |
| DashSlash의 Windup·베기·돌진 이동·이동 후 대기·Recovery 중 머리 피격 | 해당 GA 취소, 돌진과 공격 피해 중단 후 기절 |
| ChainSlashDash의 첫 회차 또는 후속 회차 머리 피격 | 연속 GA 전체 취소, 다음 회차 예약 제거 후 기절 |
| Vanish 계열의 노출된 준비·재등장·공격 중 머리 피격 | 실행 중 전투 GA 취소 후 기절 |
| Gunner의 조준·단발·연사 중 머리 피격 | 전투 GA 취소, 잔여 발사 예약 중단 후 기절 |
| 대기·일반 이동 중 머리 피격 | 기존처럼 머리 피격만으로 기절하지 않음 |
| 몸통 피격 또는 지속 피해 | 머리 피격 기절을 발생시키지 않음 |
| 은신으로 피격 충돌이 꺼진 상태 | 직접 피격을 받지 않음 |
| 기절 중 추가 피격 | 기존 기절의 시간 연장·중첩 없음 |
| 치명타로 사망 | 사망 처리가 우선하며 기절을 새로 적용하지 않음 |

기절 기본 시간은 보스의 `HeadHitStunDuration` 4초를 유지한다. 보스 Blueprint에서 이미 설정한 값은 그대로 사용한다. 체력 임계치 기절, 기절 VFX, 면역 정책도 기존 시스템을 사용한다.

여기서 대상 GA는 보스의 전투 패턴이다. 기절·사망·상호작용 등 모든 활성 GA를 머리 기절 조건으로 취급하지 않는다. Recovery도 전투 GA가 끝나기 전이므로 포함한다.

## 2. 확인한 현재 구조와 원인 조사

1. `Source/Enemy/Private/BossAI/ShipBossEnemy.cpp`의 `HandleConfirmedDamage()`는 양수 피해, 비주기 피해, `StunHeadBones`에 포함된 피격 뼈, `State_Attacking`을 검사한다. Windup 구간을 직접 제한하는 조건은 없다.
2. `UBossGameplayAbility`는 `State_Attacking`을 `ActivationOwnedTags`로 보유한다. DashSlash와 ChainSlashDash는 이 계열이므로 네이티브 코드상 실행 전체가 머리 피격 기절 조건에 들어간다.
3. `UGA_BossBasicAttack`은 `UBossGameplayAbility`가 아닌 `UGA_BasicAttack` 계열이다. 기본 공격의 `State_Attacking`은 별도 로직에서 추가·제거한다. Vanish 계열도 기본 공격을 상속하므로 한쪽 부모만 바꾸면 적용 구간이 통일되지 않는다.
4. `UStunGameplayAbility`는 서버에서 제어 차단 중 허용되지 않는 활성 능력을 취소한 뒤 AI와 이동을 정지시킨다. DashSlash가 BT 분기 종료를 견디는 설정은 GAS 기절 취소를 막는 설정과 다르다.
5. `UGA_BossDashSlash::EndAbility()`와 실행 Task의 `OnDestroy()`에는 타이머, 돌진 피해 충돌, Dashing 상태, 충전 Cue, 경고 경로, 몽타주 등을 정리하는 코드가 이미 있다. 실제 기절 경로에서 모두 실행되는지는 회귀 검증이 필요하다.
6. `UCombatHurtboxComponent`는 보스의 애니메이션 PhysicsAsset 피격을 사용하며, 보스 메시와 유효한 Physics body의 `BoneName`이 필요하다. 이동 캡슐이나 임의의 추가 Sphere에 맞은 결과는 현재 구조에서 인정되지 않는다.
7. `UBaseHealthComponent`는 확정 피해 콜백을 일반 HitReaction 이벤트보다 먼저 호출한다. 이 순서를 유지해 머리 기절 판정 전에 일반 피격 반응이 공격 상태를 제거하지 않도록 한다.

따라서 “Windup 제한 하나를 제거하면 해결된다”는 결론은 현재 소스와 맞지 않는다. 구현 첫 단계에서 Samurai의 실제 BPGA 연결과 상속된 태그, 서버의 피격 BoneName, 충돌 활성 상태를 기록해 돌진 중 미발동 원인을 구분한다.

## 3. 구현 방안

### A. 기절 가능한 시간을 전투 GA 수명으로 통일

- 보스 전투 전용 상태 태그 `State.Boss.HeadHitStunEligible`을 추가한다. 이름은 기존 태그 등록 방식에 맞춘다.
- `UBossGameplayAbility`와 `UGA_BossBasicAttack`의 `ActivationOwnedTags`에 추가한다. 이를 통해 두 상속 경로와 Vanish·Dash·Gunner 파생 능력에 동일한 규칙을 적용한다.
- `HandleConfirmedDamage()`의 시간 조건을 새 태그로 바꾼다. 뼈, 확정 피해, 서버 권한, 주기 피해 제외 조건은 유지한다.
- GA가 끝나거나 취소되면 태그가 자동으로 제거되도록 GAS 소유 태그 방식을 사용한다. AnimNotify나 별도 타이머로 판정 구간을 관리하지 않는다.
- 실제 보스 BP에 부여된 레거시 또는 별도 Blueprint GA가 있다면 목록을 조사하여 대상 전투 GA에 같은 규칙을 적용한다. Blueprint가 부모의 태그 배열을 덮어쓴 경우에도 로드 후 값으로 확인한다.
- `State_Attacking` 자체의 의미나 수명을 바꾸지 않는다. 기존 기본 공격·AI·충돌 회피 동작에 영향을 주지 않고 기절 가능 구간만 명확히 한다.

### B. 기존 기절 시스템을 통해 취소하고 잔여 실행 차단

흐름은 `확정 머리 피해 → 기존 Boss HeadHit Stun GE 적용 → Stun GA 활성화 → 전투 GA 취소·정리 → AI/이동 정지`로 유지한다.

- 피해 콜백에서 모든 GA를 직접 취소하지 않는다. 기절 GE가 면역 등의 이유로 거절되면 공격도 취소되지 않아야 한다.
- 대상 전투 GA가 기절 취소를 허용하는지, Blueprint나 런타임에서 취소 불가 설정을 하지 않는지 확인한다.
- 기절 중 새 전투 GA가 시작되지 않는지 공통 제어 차단 규칙을 확인한다. 빠진 파생 클래스에만 보완한다.
- 취소가 끝난 뒤 이전 GA 정리가 기절의 AI 잠금·회전 제한을 해제하지 않도록 기존 “전투 취소 후 기절 잠금” 순서를 유지한다.

DashSlash의 취소 완료 조건:

1. Windup·Dash 이동·베기 완료·Recovery·Watchdog 타이머가 해제된다.
2. 돌진 위치 갱신이 중단된다. CharacterMovement 정지만으로는 충분하지 않다. 현재 돌진은 타이머에서 `SetActorLocationAndRotation()`을 호출한다.
3. DashDamageVolume과 피해 Resolver의 창이 닫히고, 남은 overlap·sweep·AnimNotify가 추가 피해를 적용하지 못한다.
4. 돌진 몽타주·충전 Cue·진행 전 경고 표시가 정리된다. 실행 경로의 잔상은 현재 표시용으로 일정 시간 남는 구조이므로 피해와 분리해 확인한다.
5. Dashing·Busy·기절 가능 상태와 목적지 예약이 남지 않는다. 이미 발생한 피해를 되돌리지는 않는다.
6. ChainSlashDash의 `NextStepTimer`, 재등장 Task, 타깃 추적 Task도 정리하여 다음 회차가 실행되지 않는다.
7. 기절은 현재 갑판 위치에서 유지하고, 해제 후 AI가 새 행동과 목적지를 선택한다. 취소된 돌진의 도착점으로 이동시키지 않는다.
8. 기절 취소를 목적지 선정 실패로 기록하여 Samurai의 재배치 복구 정책이 불필요하게 실행되지 않도록 확인한다. 쿨타임은 단발·연속 패턴의 기존 소비 규칙을 유지한다.

기존 정리 코드로 위 조건이 충족되면 재사용한다. 실패하는 경로만 보완하며, 기절 동안 Task가 재진입하거나 피해를 계속 처리하는 경우에는 Task의 유효성·상태 검사도 강화한다.

Gunner는 일반 피격 반응을 막는 설정과 기절 취소를 구분한다. 잔여 연사 타이머와 조준 처리의 취소를 별도로 확인한다.

### C. 실제 머리 피격 범위 확대

기본안은 추가 Sphere를 붙이는 방식보다 기존 PhysicsAsset의 머리 body를 확대하는 것이다. 실제 피격이 더 쉬워지고 `BoneName=head` 전달, 조준 위치와 실제 화살 명중 표면을 같은 구조로 유지할 수 있다.

- 각 보스 Blueprint의 실제 메시·PhysicsAsset override·머리 body 이름·캐릭터 배율을 조사한다. 현재 작성 스크립트는 공통 보스에 Samurai PhysicsAsset을 연결하지만, 모든 파생 BP의 현재 설정까지 증명하지는 않는다.
- 공유 원본을 보존하고 보스별 전용 PhysicsAsset 사본을 만들어 해당 BP의 메시 override에 연결한다. 동일 메시를 사용하는 보스는 적절히 공유할 수 있다.
- 머리 body의 중심과 회전을 실제 머리 위치에 맞춘 뒤, 반경과 길이 등 선형 치수를 약 **1.3배**로 시작한다. 실제 치수를 확인하기 전의 초기 튜닝 제안이며 확정값은 아니다.
- 전신 피격도 개선할 수 있도록 몸통·팔·다리 body를 함께 확인한다. 너무 작은 body만 **1.1~1.15배** 수준의 선택적 확대를 검토하고, 머리 확대를 우선 적용한다.
- 목·어깨·가슴까지 과도하게 머리 판정이 내려오지 않도록 경계를 조정한다. 뼈 목록에 목이나 척추를 무조건 추가하는 방식은 사용하지 않는다.
- 머리 body 충돌 활성, `CombatHurtbox`와 `Arrow`·`WeaponAim` 응답, 서버의 항상 갱신되는 애니메이션 뼈 설정을 유지한다. 이동 캡슐과 플레이어를 때리는 `DashHitRadius`는 보스의 머리 피격 크기와 별개다.
- PhysicsAsset 복제·형상 변경이 사망 연출과 물리 동작에 미치는 영향도 확인한다.
- 정지 상태뿐 아니라 Windup, 실제 베기, 돌진 자세, Recovery에서 전·측·후방으로 경계 피격을 확인한다.
- 고속 돌진 중 명중 누락이 남으면 충돌체를 계속 키우기 전에 발사체 이동 sweep, 보스의 위치 갱신과 서버 뼈 갱신 순서를 조사한다. 고속 이동의 충돌 누락은 별도 원인일 수 있다.

## 5. 검증 및 완료 기준

### 자동화 검증

- 실제 대상 전투 GA 활성화 후 머리 피해를 주어 기절 상태와 GA 취소를 함께 확인한다. 태그만 수동으로 넣는 기존 상태 테스트만으로 완료하지 않는다.
- 기본 공격의 준비·공격·후딜, 단발 DashSlash의 Windup·이동·Recovery, 연속 DashSlash의 후속 회차를 나누어 확인한다.
- 기절 적용 후 여러 프레임을 진행해 돌진 위치 변화, 추가 피해, 후속 회차 실행이 없는지 확인한다. 선박 자체 이동은 돌진 이동과 구분한다.
- 새 PhysicsAsset에서 기존에는 빗나가던 머리 경계 trace가 메시의 머리 body에 맞는지, 확대 바깥은 빗나가는지 확인한다. 테스트가 다른 몸통 body를 맞고도 통과하지 않도록 `BoneName`까지 검사한다.
- 화살 피격 adapter → 확정 피해 → 기절 → GA 취소 전체 경로를 확인한다.
- 대기 머리 피격, 공격 중 몸통 피격, 지속 피해, 기절 면역, 중복 기절, 치명 피격, 체력 임계치 기절 회귀를 확인한다.
- 기존 Boss 상태·Hurtbox·Dash 관련 테스트와 Editor 빌드를 실행한다.

### PIE 및 네트워크 검증

- 실제 Samurai가 플레이어를 향해 돌진할 때 확대된 머리 범위를 맞춘다. 피격 직후 돌진과 베기가 중단되고 현재 위치에서 기존 기절 별 VFX와 설정된 지속 시간이 적용되어야 한다.
- 기절 종료 후 보스가 굳거나 이전 목적지로 튀지 않고 다음 행동을 선택해야 한다.
- 첫 회차와 후속 회차를 각각 끊어 연속 공격 전체가 끝나는지 확인한다.
- 다른 보스의 실제 전투 GA에도 같은 규칙이 적용되는지 확인한다.
- 서버/클라이언트에서 피격 부위, GA 종료, 위치, 기절 표시가 일치하는지 확인하고, 화면 밖의 보스 뼈 갱신과 움직이는 선박 위에서도 검증한다.
- 정상 완주 시 공격 범위·피해 횟수·쿨타임·사망 연출이 유지되는지 확인한다.

완료 기준은 **“공격 GA 실행 중 확대된 머리 범위에 확정 직접 피해가 들어오면, 서버에서 기절이 적용되고 현재 패턴과 남은 이동·피해·후속 실행이 멈추며, 기절 종료 후 정상 전투로 복귀한다”**이다.

## 6. 진행 순서
