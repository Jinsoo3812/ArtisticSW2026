# Deck Enemy 충돌 Point 해제·반대 방향 재탐색 구현

## 적용 범위

일반 Deck Enemy의 접근, 쿨다운 측면 이동, LOS 복구, 순찰, 조사와 Boss의 일반 보행에 적용한다. Ground Enemy의 NavMesh 이동, Boss Dash/Vanish의 목적지 선택·실행은 이 재탐색 정책에 연결하지 않는다.

일반 Enemy와 Boss의 기본 CharacterMovement를 `UDeckEnemyCharacterMovementComponent`로 지정했다. 이 컴포넌트는 기존 CMC 이동·복제를 유지하면서 실제 impact와 침투 보정을 Route에 전달한다. 생성자에서 기본 이동 컴포넌트 클래스를 바꿨으므로 **Editor를 종료하고 전체 빌드 후 다시 열어 확인**한다. 기존 BP가 이동 컴포넌트를 별도로 교체했다면 실제 클래스도 확인한다.

## 실행 흐름

1. 이동 전 실제 캡슐로 가까운 구간을 검사한다. 이동 중 CMC impact/침투는 세대 번호와 함께 기록만 한다.
2. 이동 Task의 안전한 Tick에서 Player/Pawn/물체 blocking, 침투 또는 진행 정체를 확인하고 `Blocked`를 반환한다.
3. 정리 전에 실패 Goal, 접촉 구역·보행면, 충돌 컴포넌트, 충돌 반대 방향을 기록한다.
4. 보행 입력을 중지하고 Point, Claim, Route, 이동 Blackboard 값을 해제한다. Combat 타깃을 삭제하지 않는다.
5. 공통 재탐색 간격 후 새 Goal과 경로를 검사·예약·설치한다. 실패한 선택을 BT 성공으로 바꾸지 않는다.

접촉 법선의 갑판 평면 방향을 충돌 반대 방향으로 사용한다. 이 방향을 구할 수 없는 정체는 마지막 경로 진행 방향의 반대편을 사용한다. 안전하지 않은 곳으로 강제로 이동시키지는 않는다.

## 목적지와 경로

- 충돌 반대 방향에 있는 후보를 우선 평가한다. 접근/측면 이동에서는 기존 이상 목적지 주변 후보에 현재 위치로부터 350 cm 이내의 탈출 후보를 추가한다. 탈출 중에는 거리 띠 경로 제약을 잠시 해제하고, 정상 사거리·거리 띠 선택은 이후 새 이동에서 재평가한다.
- 조사/LOS 복구는 원래 조사·복구 위치 주변이라는 의미를 유지하면서 가능한 후보 중 충돌 반대편을 우선한다. 안전 후보가 없다면 실패하거나 제한 재시도한다.
- 최근 실패 Goal의 노드 및 60 cm 이내의 인접 위치를 잠시 제외한다. 같은 보행면의 접촉 구역 75 cm 안에서 장애물 방향으로 다시 진입하는 edge도 제외한다. 그 구역에서 반대편으로 빠져나오는 방향은 허용한다.
- 목적지가 비어 있어도 경로 전체가 막힐 수 있으므로 A* edge마다 현재 캡슐 통과 여부를 검사한다. 이 필터는 질의마다 적용하며 공유 그래프의 enabled 상태를 변경하지 않는다.
- 이동 중에도 가까운 구간을 다시 검사하여 그래프 생성 후 들어온 Player/물체를 감지한다. 검사에는 타깃 외의 Player, Pawn, 물체도 포함한다.
- 경로 시작점은 샘플 노드 중심 대신 실제 발 위치를 사용한다. precise Goal의 마지막 연결 구간도 지지·통과 여부를 검사한다.
- 후보 탐색은 최대 12회, 반대 방향 후보는 우선 최대 6회 평가하여 나머지 방향도 검토할 기회를 남긴다. Actor 추적·순찰도 유한한 후보 예산을 사용한다.
- 그래프 경로 질의의 구간 검사는 최대 256회, 일반 Route의 같은 서버 시간 업데이트 내 설치 질의는 합산 512회로 제한한다. Boss 선택 단계도 512회 예산을 사용하고 실제 설치에서 다시 검증한다. 예산 부족은 검사하지 않은 경로의 허용으로 처리하지 않는다. 단차 재검사는 구간당 추가 sweep가 발생할 수 있다.

## 정상 접촉·공격·피격 보호

실제 캡슐 크기, 회전, collision object type, response container와 이동 ignore 목록을 사용한다. HostShip 전체를 무시하지 않으므로 동일 선체의 난간도 장애물로 검사한다. 비blocking 감지/피해 volume은 이동 장애로 취급하지 않는다.

정상 walkable 바닥/경사와 얕은 바닥 접지는 제외한다. 낮은 물체는 CMC의 StepUp 자격과 높이를 확인하고 올린 캡슐로 다시 검사한다. Pawn의 캡슐을 일반 보행 바닥/계단으로 간주하지 않는다. 가벼운 벽면 측면 접촉은 진행 방향과 법선을 비교하여 제외하고 실제 정체가 지속되면 처리한다.

Brain 일시정지·resource lock, 공격 commit/공격 태그, 피격, 스턴, 이동 차단, Knockback, Boss Busy, Root Motion 중에는 일반 보행의 정체를 누적하지 않는다. Task 정리도 이 상태의 외력/Root Motion 속도를 지우지 않는다. 기존 공격 준비 우선순위는 유지한다.

이미 침투한 경우에는 일반 보행 또는 충돌 재탐색 대기 중에 안전한 수평 보정을 먼저 검토한다. 같은 보행면, 발 높이 차이 5 cm 이내, 실제 캡슐의 빈 공간을 모두 확인한 최대 60 cm 이내의 후보만 CMC에 전달한다. 안전한 수평 후보가 없으면 기존 CMC 보정을 유지한다. 모든 피격 상황에서 난간 올라탐을 해결하는 별도 물리 정책이나 보행면 이탈 복구를 이번 변경으로 대체하지 않는다.

## BT 계약

- `SelectDeckWaypoint`: 새 경로 설치 완료일 때만 성공한다. 예전 Route가 남았다는 이유로 성공하거나 내부 0.3초 대기로 선택 실패를 숨기지 않는다.
- `MoveAroundDeckTarget`: 새 측면 경로 계획 실패를 타깃 유효성만으로 계속 진행하지 않는다.
- 일반 이동이 `Blocked`이면 정리 후 실패를 반환하여 기존 BT의 Wait/재선택 흐름을 사용한다. 타깃·Combat 상태는 유지한다.
- **조사 이동 예외:** 기존 Investigating BT는 이동 실패 후 Passive로 전환하므로, 실제 충돌에 대해서는 이동 Task 안에서 조사 위치를 배 로컬 좌표로 보존하고 최대 3회의 교체 계획을 시도한다. Point/Claim은 충돌 시 바로 해제한다. 준비 전에는 이동하지 않고, 경로 설치 완료 후 기존 이동 Task를 계속한다. 계획 실패 또는 반복 충돌 한도 초과 시 기존 실패 흐름으로 돌아간다. 최초 목적지 선택 실패는 그대로 실패다.

## 반복 실패와 수명

기본 재탐색 간격은 0.25초이며 개체 ID에 따른 0~0.06초의 작은 차이를 추가하여 군집의 동시 재시도를 분산한다. 반복 시도가 4회 이상이면 0.8초 간격으로 늦춘다. 이 gate는 접근·측면 이동·조사·복구·순찰에 공통 적용되어 같은 Tick의 다른 BT 분기에서도 재탐색이 중복되지 않는다.

최근 실패 기억은 기본 1.25초이고 최대 6개다. blocker가 파괴되거나 query collision이 꺼지거나 배 로컬 위치가 50 cm 이상 바뀌면 조기에 해제한다. 새 경로 설치와 일반 `ClearGoal()`은 반복 실패 기록을 초기화하지 않는다. 실제 로컬 이동 100 cm 이상 또는 유효 목적지 도달 때 재시도 예산을 회복한다.

Host/그래프 revision 변경, 일반 Enemy 풀 반환·사망·스냅샷 복원, Boss 초기화·사망·복원·종료에서는 기록을 초기화한다. 경로 설치/정리에 세대 번호를 바꾸어 이전 impact를 새 경로에 전달하지 않는다. 아직 처리하지 않은 impact가 있으면 타깃 이동에 따른 교체 계획으로 덮어쓰지 않는다.

종점 Claim은 중간 통로 예약을 뜻하지 않는다. 이번 구현은 live Pawn 검사, 반대 방향 이동, 재시도 분산과 제한 대기로 군집 충돌에 대응한다. 함선 공유 장애 캐시와 독점 통로 예약/우선권 시스템은 추가하지 않았다.

## 설정·관측

`DeckWalkRouteComponent`의 `Deck AI | Collision` 설정:

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| Avoid Movement Collisions | true | 일반 보행 충돌 검사·회피 |
| Block Memory Seconds | 1.25초 | 실패 지점·방향 기억 |
| Collision Replan Interval | 0.25초 | 기본 공통 탐색 간격 |
| Collision Look Ahead | 60 cm | 최소 전방 검사 길이. 속도의 0.15초 예상 이동과 비교하여 큰 값 사용 |
| Draw Collision Debug | false | 새 경로 녹색, 해제 Goal 빨강, 선호 탈출 방향 청록 표시 |

원인 없는 진행 정체는 기존 Task timeout과 0.3초 중 작은 값을 사용한다. 확정된 전방 blocking/침투는 이 timeout을 기다리지 않는다.

진행 거리 기준은 실제 허용 속도·가속도에 맞춰 줄여 Slow 효과/낮은 가속도를 빈 갑판의 막힘으로 오인하지 않도록 한다. 허용 속도 0인 대기는 정체 시간을 누적하지 않는다.

`Log LogTemp Verbose`를 활성화하면 `[DeckWalkBlocked]`의 Enemy, 세대, 원인, Goal, blocker, 보행면, 탈출 방향, 시도 횟수를 확인할 수 있다. 원인 값은 Player=1, Pawn=2, Geometry=3, Penetration=4, NoProgress=5다.

## 검증

사용자 요청에 따라 자동화 테스트를 추가하거나 실행하지 않았다. `ArtisticSW2026Editor Win64 Development` UE 5.7 최종 빌드는 성공했고 Source 변경의 whitespace 검사도 통과했다. PIE 실행 검증은 이번 작업에서 수행하지 않았으므로 아래 장면에서 확인한다.

1. 빈 목적지까지 가는 경로에 정지 Player를 배치한다. Goal/Claim이 해제되고 충돌 반대편 안전 후보를 우선 선택하는지 확인한다.
2. 반대편에 벽·난간이 있는 경우 강제로 뒤로 밀지 않고 다른 안전 후보 또는 제한 대기로 전환하는지 확인한다.
3. 이동 중 끼어드는 Player, 다른 적, 생성/이동한 상자·문을 각각 사용한다. 종점뿐 아니라 중간 경로가 재검증되는지 확인한다.
4. 여러 적이 좁은 통로에 모인 경우 재시도 빈도와 탐색 비용을 관측한다. 공간이 생기면 이동이 재개되는지 확인한다.
5. 정상 계단·경사·벽면 slide·함선 운동에서 잘못된 `Blocked`가 반복되지 않는지 확인한다.
6. 난간 위 Player 감지, 공격 준비/commit, 피격·스턴·Knockback, Boss Dash/Vanish가 기존 상태와 우선순위를 유지하는지 확인한다.
7. Investigating 이동이 첫 충돌로 즉시 Passive로 전환하지 않고 동일 조사 위치 주변을 제한적으로 재탐색하는지 확인한다.
8. 풀 재활성·Host 변경·체크포인트 복원에서 이전 Goal/Claim/기억이 남지 않는지 확인한다.
9. Listen/Dedicated 서버와 원격 클라이언트에서 목적지 선택이 서버에서만 이루어지고 이동 복제가 수렴하는지 확인한다.

실제 맵별 캡슐 크기·충돌 형상·단차·군집 밀도에 따라 검사 거리와 시간, 예산을 조정한다.
