# 남녀 리그·시체 시스템 팀 테스트

공유 브랜치: **JYU_merge**. 남녀 리그, 실제 플레이어 BP/ABP 연결, 체형별 PhysicsAsset 및 기존 생명주기에 연결한 시체 표현을 포함한다.

## 받기

로컬 변경은 먼저 별도 커밋하거나 보관한다. Git LFS를 사용할 수 있는 환경에서 다음 명령을 실행한다.

```powershell
git fetch origin
git switch --track origin/JYU_merge
git lfs pull
```

이미 로컬 `JYU_merge`가 있다면 `git switch JYU_merge` 후 `git pull --ff-only`와 `git lfs pull`을 실행한다. C++ 변경이 있으므로 에디터를 닫고 프로젝트의 Development Editor를 빌드한 다음 실행한다. 에디터·Live Coding·기존 빌드가 실행 중이면 먼저 정상 종료/완료를 기다린다. 블렌더 작업본을 열 필요 없이 UE에서 플레이할 수 있다.

## 플레이 확인

1. 실제 플레이 맵에서 남성 `BP_Player_Man`, 여성 `BP_Player_Woman`을 각각 선택해 idle·걷기·달리기·질주·급회전·점프·착지를 확인한다. 어깨/겨드랑이, 목, 손발과 무기 위치 및 모션매칭 전환이 갑자기 튀는지 본다.
2. 피격 사망과 방향 없는 사망을 각각 실행한다. 시체가 표시되고 바닥에 충돌하는지, 무릎/팔꿈치가 심하게 뒤집히거나 계속 떨리는지, 이동 속도가 사망 직후 갑자기 사라지는지 확인한다. 반복 사망 통지에 시체가 다시 발사되지 않아야 한다.
3. 살아 있는 캐릭터가 시체 때문에 밀리거나 카메라/조준이 가려지지 않는지 확인한다. 부착 장비는 기존 정책대로 숨긴다. 사망 카메라는 수평을 유지하며 시체가 만료되어도 갑자기 원래 위치로 뛰지 않아야 한다.
4. 기존 개별 부활 흐름(현재 지연 5초)에서 새 캐릭터 표시·입력·애니메이션·인벤토리/성장 상태가 복원되는지 확인한다. 이전 시체가 새 플레이어의 ASC나 입력을 다시 가져가면 안 된다.
5. 리슨 호스트와 게스트가 각각 사망/부활해 상대 시체도 표시되는지 확인한다. 시체 자세는 각 머신에서 로컬 시뮬레이션하므로 서로 완전히 동일할 필요는 없다.
6. 실제 이동/회전하는 배, 계단·경사·벽 근처·물가에서 추가 확인한다. 배 침몰·물속·높은 추락·지연/유실 및 패키징은 이번 자동 검증을 넘어서는 팀 확인 항목이다.

## 확인된 결과와 한계

PIE 14개 시나리오·7,200프레임, 리슨 호스트/클라이언트 사망과 새 소유 전환, native 회귀 23개가 통과했다. native 6개는 기존 콘텐츠 경고를 포함한다. 강한 충격 순간 제한 초과 최대 약 11.5°, 정착 후 최대 약 0.66°였으므로 모든 프레임에서 오차 0을 보장하는 구현은 아니다.

충돌체는 메시 표면을 완전히 덮지 않는다. 일부 신체·신발은 약 2–5cm, 긴 머리카락·가방은 그보다 더 바닥을 관통하는 최종 자세가 확인됐다. 천/머리카락 물리나 완전한 표면 충돌을 구현한 것은 아니다. 실제 회전·파도 배 환경은 평행 이동 ShipDeck proxy 테스트와 구별해 확인한다.

문제 제보에는 남/여, 맵·위치, 호스트/게스트, 사망 원인, 이동/점프/승선 상태, 재현 순서와 영상 및 `Saved/Logs`를 함께 남긴다.
