# 배 위 점프의 간단한 리팩터링

2026-10-11. 기존 CharacterMovement의 Falling과 bStayBasedInAir를 사용하는 1차 구현이다.

## 적용 동작

- 배에서 점프할 때 수직 초기 속도에 남아 있던 상승 속도를 제거하고 기존 JumpZVelocity로 시작한다.
- 배에서 전달되는 선속도와 각속도는 플레이어 Velocity에 더하지 않는다.
- 배의 Walking에서 Falling으로 전환하면 공중에서도 기존 기반 이동을 유지한다. 점프 외에 가장자리에서 떨어지는 경우도 동일한 기반 유지 규칙을 사용한다.
- 배가 회전하면 플레이어의 수평 이동 속도 방향도 배의 yaw 변화에 맞춰 회전한다.
- 배가 발밑에서 벗어나면 엔진의 바닥 질의가 기반을 해제하고 일반 낙하로 전환한다. 이때도 배 관성을 추가하지 않는다.
- 착지/수영/이동 중단 시 공중 기반 유지 설정을 해제한다. 육지와 다른 종류의 발판은 기존 점프를 사용한다.
- 같은 배의 공중 기반 이동에는 기존의 제한된 상대 위치 검증(기본 15cm)을 적용한다. 배 위에서 시작한 모든 낙하의 correction을 무조건 생략하던 분기는 제거했다.

## 구현 범위

중력은 기존 월드 수직 방향을 유지한다. 배 기울기에 맞춘 로컬 중력, 과거 배 프레임의 충돌 재생, 별도 custom jump mode는 이번 간단한 구현에 포함하지 않았다. 큰 roll/pitch와 네트워크 지연에서 완벽히 동일한 점프/착지를 보장하는 전체 설계는 Planning/Network Physics/Player_Ship_Independent_Jump_Plan_2026-10-11.md를 따른다.

기존 JumpMaxHoldTime 및 공중 제어 설정은 유지한다. 동일한 출발 속도와 입력 시간끼리 비교한다. 공중 기반 높이 질의는 기존 StayBasedInAirHeight와 계산된 점프 정점 높이+여유 중 큰 값을 사용한다.

## 수동 확인 순서

1. 정지 배와 전진/후진 배에서 입력 없이 점프한다. 배 위 상대 위치가 유지되는지 확인한다.
2. 같은 달리기 입력으로 배의 이동 방향과 반대 방향에 각각 점프한다. 배 속도로 추진력이 달라지지 않는지 비교한다.
3. 회전하는 배에서 점프한다. 상대 이동 방향과 카메라 회전을 확인한다.
4. 난간과 천장 아래에서 점프하고 착지한다. 걸림/관통/반복 보정을 확인한다.
5. 배 밖으로 뛰어나가 육지/다른 배/바다로 이동한다. 공중 추종이 종료되고 정상 낙하·착지·수영으로 전환되는지 확인한다.
6. 서버와 원격 클라이언트에서 같은 항목을 반복하고 p.NetShowCorrections 1로 확인한다. 보정 표시만이 아니라 양쪽 상대 위치도 비교한다.
7. 공중 피격·사망·리스폰 및 육지 점프가 정상인지 확인한다.

자동화 테스트는 요청에 따라 생략한다. 실제 PIE 플레이 검증 결과와 빌드 결과는 별도로 구분한다.
