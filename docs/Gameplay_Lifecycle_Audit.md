# 게임플레이 상태·수명 주기 점검 (2026-10-31)

승선 후 구르기 제보를 시작으로 전투, 제작, 아이템 획득/인벤토리, 승선, 애니메이션의 상태 소유권과 비동기 종료 경로를 점검했다. 실제로 확인한 원인을 수정하고, 잘못된 입력·파괴된 대상·중복 알림에 대한 방어를 추가했다. 프로젝트 전체의 모든 버그가 없음을 보장하는 검사는 아니다.

## 원인 수정

| 영역 | 기존 문제 | 변경 |
| --- | --- | --- |
| 수영 → 승선 | 배가 직접 Walking으로 바꾸면 기존 수심 검사 기반 종료가 실행되지 않아 수영 태그가 남음 | 이동 모드 이탈 콜백에서 즉시 수영 상태·입력·캐시 해제. [승선 상세](Ship_Boarding_Roll.md) |
| 조준·공격·제작 태그 | 획득 전 실패, 확정 후 종료, 반복 종료가 다른 기능의 같은 태그 카운트를 감소시킬 수 있음 | `FSWOwnedLooseGameplayTags`가 ASC와 획득한 태그를 기억하고 자기 기여분만 한 번 해제 |
| 상호작용 TargetData | GAS 캐시에 대한 참조를 Consume한 후 읽으면 이미 도착한 데이터가 비어 있을 수 있음 | 핸들을 먼저 복사하고 캐시 소비. 종료 시 해당 구독과 캐시 정리 |
| 제작 가능 수량 | 같은 재료가 여러 줄이거나 소비하는 레시피 아이템과 겹치면 화면이 실제 비용보다 적게 계산 | 서버 거래와 동일한 `BuildCosts` 합산을 가능 여부·최대 수량에 사용 |
| 산탄 수류탄 | 현재 열어둔 인벤토리 탭에 따라 자탄 재료 탐색 결과가 달라짐 | Material 탭을 명시해 검색 |
| 수류탄 투척 | 반복 노티파이/입력 해제로 추가 스폰 가능, 스폰 실패에도 아이템 소비 | 해제/커밋 단계 구분, 발사 1회 제한, 유효한 투사체 생성 후 본체 소비 |
| 수류탄 취소 | 실제 Blueprint에 수영/구르기/피격 취소용 능력 태그가 없어 조준 능력이 계속 활성 상태로 남을 수 있음 | 네이티브 기본값에 AimCycle/InterruptibleByHit를 지정하고 실제 Blueprint의 상속도 검사 |
| 제작 UI | 잘못된 작업대 역참조, 중복 이벤트 연결·태그 누적, 오래된 닫기 요청이 새 작업대 세션을 종료할 수 있음 | 대상 검증, 연결 멱등성, 서버/표시 작업대 분리, 닫을 작업대 식별 |
| 즉시 종료되는 능력 태스크 | ReadyForActivation 중 입력/확정이 동기 처리되어 능력이 종료돼도 후속 태스크·프리뷰를 만들 수 있음 | 해당 활성화 구간에 IsActive 확인 |

태그 헬퍼는 활 조준/드로우/발사, 기본 공격, 중력 소용돌이, 수류탄, 제작자 역할/제작 UI, 수영에 적용했다. 소멸자에서 UObject에 접근하지 않고 EndAbility/EndPlay에서 명시적으로 Reset한다. ASC가 바뀌어도 기존 ASC에 획득했던 카운트를 반환한다. 범위 둔화는 기존의 획득 여부 추적을 유지한다.

실제 수류탄 Blueprint 두 개의 ActivationOwnedTags에 있던 `State.Aiming`은 제거했다. 이제 네이티브 코드가 조준 유지 → 입력 해제 → 종료 단계에 맞게 소유한다. 이 에셋 변경과 네이티브 코드는 함께 적용해야 한다.

## 예외·서버 검증 보강

- 상호작용: 같은 월드, 살아 있는 대상/플레이어, 비활성 풀 객체/충돌 비활성 여부, 컴포넌트 bounds 기준 도달 거리 확인. 배 원점이 멀어도 근처 승선 컴포넌트는 허용한다. 원격 TargetData 누락은 5초 후 종료한다. 콜백이 대상을 파괴하면 후속 이벤트를 보내지 않는다.
- 입력 전달 RPC: 정확한 마우스 입력 태그 6개만 허용하고 Instigator를 호출 플레이어로 정규화한다. 클라이언트가 획득·제작 완료·몽타주 결과 이벤트를 이 RPC로 직접 전달할 수 없게 한다. 활 입력의 TargetData는 유지한다.
- 저격: 서버에서 유효한 대상·월드·사거리·발사 간격을 확인하고 시선 위치에서 다시 트레이스한다. 벽 뒤 대상/조작된 히트의 피해를 거부하고 서버 히트로 피해 컨텍스트를 만든다. 수영/피격 취소 태그를 부여하고 메시 숨김은 원래 값으로 복원한다. 종료 시 TargetData 구독도 해제한다.
- 제작: 서버가 열어준 작업대 세션과 거리 확인, 음수/비유한 오차·길이 거부. UI 종료가 다른 통합 UI의 입력 모드를 덮어쓰지 않도록 하고 자신이 연 위젯·컨텍스트·태그만 정리한다. 아이템 삽입 실패 시 월드 아이템을 보존한다.
- 인벤토리: 수량 합산에 int64를 사용하고 int32 상한에서 포화시킨다. 잘못된 음수 스택은 정상 재고를 상쇄하지 않는다.
- 산탄 수류탄: 선택 인덱스·자탄 클래스·실재 재고 검증 후 소비하고 생성 실패는 종료한다. FinishSpawning 도중 파괴되면 자탄 반환을 시도한다.

## 검증 방법과 범위

네이티브 검사는 실제 GAS/인벤토리/제작 코드와 가상 월드를 사용한다. 새 검사는 태그 소유권, ASC 교체, RPC 결과 이벤트 차단, 캐시 수명, 상호작용 거리/비활성, 수량 오버플로, 제작 세션, 저격 벽/거리, 수류탄 실패/단계/단일 커밋을 포함한다. 기존 전투·제작·수영·대포·발 배치·점프/정지 애니메이션·장비·공유 창고·대화·스킬·사망/재생성·상자 풀·배 강화·카메라 검사도 함께 실행한다.

기존 물폭탄 대포 검사는 BeginPlay 없는 가상 월드에서 속성 등록을 생략해 체력 초기화 ensure가 있었고, 일반 PlayerController를 사용해 현재 생명주기 권한 정책도 통과하지 못했다. 실제 BasePlayerController와 속성 등록을 사용하는 공통 player-life fixture로 통일했다. 제작 추가 검사는 후속 목록 검사 전에 원래 테스트 레시피를 복원한다.

`Scripts/Editor/GameplayLifecycleAudit/run_audit.py`는 모든 완료 로그를 누적하고 실패가 없을 때 2인 승선 재현을 이어간다. 기존 `Scripts/Editor/probe_world_audio.py` 브리지의 `run_script`로 실행하며, `run_audit.py`, `boarding_roll.py`, `setup_pie.py`, `restore_pie.py`를 `Saved/AudioIntegration/LiveScripts/`에 준비한다. 완료 후 PIE를 종료하고 `restore_pie.py`를 실행해 설정을 복원한다. 검증 전용 승선/이동 API는 Editor 모듈에만 있다.

최종 직접 UBT 빌드는 성공했고, 자동 검사 **89/89**, 남녀 2인 승선·C 구르기 **8/8**이 통과했다. 직전 실행에서도 89/89 및 8/8을 확인한 뒤 수류탄 취소 태그를 추가했고, 최종 코드로 전체 흐름을 다시 통과했다. 실제 수류탄 두 Blueprint와 저격 Blueprint의 상속 태그도 새 에디터에서 확인했다.

최종 결과는 [정량 보고서](validation/Gameplay_Lifecycle_Audit_20261031.json)에 있다. 빌드 로그는 `Saved/GameplayLifecycleAudit/Build_Publish.log`, 자동 검사/PIE 로그는 `Audit_Publish.log`, 표본은 `Saved/AudioIntegration/Live/7104/`다. 원본 로그와 표본은 Saved에 보존하고, 커밋에는 재실행 코드와 작은 정량 요약을 포함한다.

## 남은 검증 범위

- 2인 listen-server 검증 외 전용 서버, 고지연/패킷 손실, 장시간 재접속·심리스 트래블, 모든 맵/캐릭터/스킬 조합은 별도 플레이 검증이 필요하다.
- 파밍은 공통 상호작용/인벤토리/공유 창고/상자 풀 경로를 검사했다. 모든 채집 노드·드롭 테이블·보스 보상 확률을 전수 재생하지 않았다.
- 레거시 스타포스 미니게임은 세션·거리·숫자를 검증하지만 성공 타이밍 자체는 여전히 클라이언트 보고다. 서버 주도 시도 ID/타이밍 프로토콜은 별도 설계가 필요하다. 기본 통합 제작의 원자적 비용/배달 거래는 유지한다.
- 저격 검증은 현재 서버 월드 기준이다. 지연 보상/과거 위치 판정이나 완전한 조준각 부정행위 검증을 구현한 것은 아니다.
- 산탄 생성 중 재료를 먼저 소비하는 경로에서 투사체 BeginPlay가 인벤토리를 재진입 변경하고 파괴되는 극단적 경우, 반환 공간 예약까지 보장하지 않는다.
- 기존 에셋 로딩 경고(실험용 PSD 참조 누락)와 Room 모듈의 변수 이름 가림 경고는 이번 변경 범위에서 수정하지 않았다. 테스트 실패를 숨기도록 필터/경고 수준을 낮추지 않았다.

위 코드 변경은 확인된 상태/수명 주기 원인 수정 및 잘못된 요청에 대한 방어다. 임시 파일 정리는 저장 공간 정리이며 게임플레이나 엔진 종료 문제의 원인 수정으로 간주하지 않는다.
