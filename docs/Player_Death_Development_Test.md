# 플레이어 사망·래그돌 개발 테스트

> **2026-10-06 병합 이후:** 아래 내용은 2026-10-04 구현의 기록이다. 현재 콘솔 사용, 10초 부활·시체 수명, 동료 관전 및 회귀 테스트는 [플레이어 생명주기 병합 통합](Player_Life_Merge_Integration_2026-10-06.md)을 따른다. 특히 전역 Session CVar와 자기 시체 추적 카메라 정책은 현재 사용하지 않는다. 마지막 Physics Asset 튜닝 기록은 에셋 확인 자료로 유지한다.

## 콘솔 사용

Development 또는 Editor 빌드에서 게임을 실행한다. 단일 프로세스 PIE의 `Play As Client`에서도 해당 플레이어 콘솔에 아래 두 명령을 순서대로 입력하면 된다. 여러 PIE 월드가 Session 값을 공유하기 때문이다. 서버와 클라이언트를 별도 프로세스로 실행하면 Session은 서버 프로세스에서 설정한다.

```text
sw.DevTest.Session 1
```

사망시킬 플레이어의 PIE/게임 창 콘솔에서 다음 명령을 입력한다. 호스트와 게스트 모두 같은 명령을 사용한다.

```text
sw.DevTest.Suicide
```

명령은 해당 콘솔 월드의 로컬 플레이어 한 명만 대상으로 한다. 관전 중이거나 배·대포를 조종해 플레이어 캐릭터를 소유하지 않은 경우 거절한다. 분할 화면처럼 로컬 플레이어가 여러 명이면 대상 선택이 모호하므로 거절한다. 전용 서버 콘솔에서 Suicide로 임의 플레이어를 선택하지 않는다.

`sw.DevTest.Input` 및 Ctrl+Alt+~ 테스트 메뉴는 구현되어 있지 않다. 이 테스트에는 입력 매핑이나 BP 키 추가가 필요 없다.

테스트 종료 후 서버에서 다음 값을 설정한다.

```text
sw.DevTest.Session 0
```

Session은 프로세스 단위의 CVar이며 복제되지 않는다. 서버와 게스트가 별도 프로세스이면 서버에서 활성화해야 한다. 단일 프로세스 PIE에서는 여러 PIE 월드가 같은 Session 값을 공유하지만 Suicide 대상은 입력한 콘솔의 월드 안에서만 찾는다. Shipping/Test 빌드에서는 두 콘솔 항목을 등록하지 않으며, 남아 있는 RPC 진입점도 사망을 실행하지 않는다.

## 처리 구조

콘솔 → 로컬 BasePlayerController → 소유 Controller의 서버 RPC → 서버 정책 확인 → ASC Health를 0으로 설정 → 기존 BaseHealthComponent/PlayerDeath GA → DeathFinished → 기존 래그돌·부활 처리.

클라이언트가 요청 당시의 Pawn을 전달한다. 서버는 그 Pawn이 현재 Controller의 플레이어인지 다시 확인한다. 소유권 변경·부활 이후 늦게 도착한 요청은 새 Pawn에 적용하지 않는다. 이미 사망한 Pawn은 중복 처리하지 않으며, ASC의 Avatar와 현재 Pawn이 일치하는지 확인한다. 기존 사망 흐름 이외의 시체 생성·물리 활성화·부활 타이머를 테스트 명령에서 만들지 않는다.

사망 완료 시 진행 상황을 먼저 저장하고, 시체의 체력/상태/전투 표시 및 상호작용 이벤트 ASC 구독을 해제한다. PlayerState의 ASC는 그대로 유지해 새 Pawn이 사용한다. 이전 시체의 PlayerState가 늦게 복제되더라도 사망 완료된 Pawn은 ASC Avatar와 인벤토리 소스를 다시 연결하지 않는다. 시체 삭제까지 살아 있는 Pawn의 체력/상호작용을 이전 시체가 구독하는 상황을 막는다.

서버 로그와 요청한 클라이언트 콘솔에서 `[DevDeath]`를 확인한다. Started는 사망 흐름이 시작됐다는 뜻이며, 화면의 물리 결과나 부활 완료를 보증하는 메시지는 아니다. Disabled는 서버 Session 설정, InvalidPawn은 관전/다른 Pawn/지연 요청, NotReady는 ASC·체력 초기화를 확인한다.

## 검증

자동화 명령:

```text
Automation RunTests ArtisticSW.Player.Death+ArtisticSW.GameMode.PlayerCorpseLifecycle+ArtisticSW.Enemy.DeathRagdoll
```

자동화는 서버 opt-in, 다른 Pawn·빈 Pawn·비권한·에디터 월드 거절, 체력 0과 기존 사망 상태/태그, 무방향 사망, 중복 요청을 확인한다. PlayerState의 체력 0/사망 태그를 유지한 채 새 Pawn을 빙의해 정상 체력·생존 상태로 복구되는지, 교체 후 지연 요청 거절과 재실행도 확인한다. 플레이어 서버 빙의 시 체력 초기화의 자동 사망 검사를 잠시 미뤄 기존 ASC의 사망 상태를 먼저 초기화한다. 다른 HealthComponent 사용처는 기존 자동 사망 검사를 유지한다. 실제 네트워크 RPC 전달, 남녀 Physics Asset, 관전 화면 및 GameMode 부활 스폰은 별도 PIE 검증이 필요하다.

PIE에서 남녀 캐릭터를 각각 정지/달리기/공중/검·활 장착 상태로 테스트한다. 호스트와 게스트 각각 명령을 실행해 양쪽 화면의 사망·래그돌·관전·부활을 확인한다. 움직이는 갑판, 물 추락, 부활 후 재사망, 전멸·레벨 재시작도 확인한다.

부활 시 새 Pawn을 생성한다. 이전 Pawn은 부활 대기 중에는 수명 제한을 해제해 보존하고, 새 Pawn 빙의가 성공한 뒤 삭제 타이머를 설정한다. 기본값은 사망 완료 후 최소 30초, 부활 후 최소 5초이다. 실제 삭제까지 남은 시간은 `max(MinimumCorpseLifetime - 사망 후 경과 시간, CorpseLifetimeAfterRespawn, 0.1초)`이다. 배의 부활 지점이 없거나 스폰에 실패하면 기본 1초 간격으로 재시도한다. 대기 중 접속이 종료되면 해당 시체와 재시도 타이머를 정리한다. 전멸 시 기존 레벨 재시작 정책으로 월드와 시체가 함께 제거된다. Physics Asset은 각 Skeletal Mesh에 별도로 연결하고 물리 에디터에서 확인한다.

## 몽타주 뒤 시체가 사라져 보이는 경우

현재 `BPGA_PlayerDeath`는 약 1.1초의 `AM_Death`를 재생한 뒤 DeathFinished에서 래그돌로 전환한다. 자살 명령도 같은 제품 사망 흐름을 사용하므로 몽타주 재생 자체는 정상이다. 즉시 래그돌이 필요하면 별도 정책으로 사망 GA의 몽타주 설정을 조정한다.

플레이어 래그돌은 Controller/PlayerState를 해제하지 않는다. 서버 GameMode가 진행 상황 저장 후 사망을 등록하고 UnPossess·부활 타이머·시체 수명을 관리한다. 플레이어는 기존 BP의 Detach 설정이 남아 있어도 이 순서를 유지한다. 일반 적의 컨트롤러 해제 정책은 유지한다.

BasePlayerController는 사망 완료 후 UnPossess할 때 시체 카메라를 서버와 소유 클라이언트에 유지한다. 관전 대상을 복제 상태로 보관하고 Pawn 복제 순서가 바뀌어도 부활 대기 중 시체를 다시 선택한다. 실제 시점 변경 RPC는 엔진 PlayerCameraManager가 보내므로 별도 중복 RPC는 호출하지 않는다. 새 Pawn을 빙의하면 엔진의 기본 카메라 관리로 복귀한다. 다른 생존 플레이어를 선택하는 관전 기능은 별도로 구현해야 한다.

`PlayerDeathCameraComponent`는 물리 계산 후 실제 골반 바디의 월드 위치를 읽어 카메라 붐의 위치만 따라가게 한다. 애니메이션 본 갱신이 화면 밖에서 생략되어도 물리 바디를 기준으로 추적한다. 게임플레이 캡슐을 이동시키거나 몸의 회전을 카메라에 적용하지 않는다. 래그돌 해제 시 기존 카메라 트랜스폼과 틱 순서를 복구한다. 기본 골반 위 오프셋은 월드 Z +45cm, 추적 보간 속도는 12이며, 물리 바디가 없으면 해당 본 또는 메시 위치를 사용한다.

에디터에서 추가 AnimGraph 작업 없이 적용된다. 캐릭터 BP의 `DeathCameraComponent`에서 `Focus Bone`, `Focus Offset`, `Follow Interp Speed`를 조정할 수 있다. 사용하는 GameMode BP의 Class Defaults에서 `Respawn` → `Individual Respawn Delay`(5초), `Respawn Retry Interval`(1초), `Respawn|Corpse` → `Minimum Corpse Lifetime`(30초), `Corpse Lifetime After Respawn`(5초)를 조정한다. 보존 시간은 물리 전환/사망 완료 시점부터 계산한다.

Output Log에서 `[PlayerDeath]`로 필터링한다.

- `DeathFinished` → `Ragdoll`: 사망 완료와 물리 전환. PhysicsAsset과 Simulating=1을 확인한다. 공용 사망 어빌리티의 임시 몽타주 완료 로그는 제거했다.
- `Registered`: 부활까지 시체 보호, 최소 보존 시간, 부활 지연, 사망/필요 플레이어 수.
- `RespawnWaiting`: 부활 지점 미확보 또는 스폰 실패로 재시도 대기. 대기 중 반복 로그는 생략한다.
- `RespawnCompleted`: 새 Pawn과 이전 시체의 실제 삭제까지 남은 시간(`CleanupIn`).
- `RegistrationSkipped`: Controller 유실, GameMode 미등록 또는 중복 등록.
- `WaitingCamera`: 부활 대기 중 시체 카메라 유지.
- `LevelRestart`: 전멸 정책에 따라 레벨을 재시작하므로 이전 시체가 제거된다.
- `EndPlay`: Pawn 종료 사유와 서버/클라이언트 구분. EndPlay Reason=0은 Destroyed, 1은 LevelTransition, 2는 EndPlayInEditor이다.

2026-10-04 저장된 에셋을 읽기 전용으로 확인했을 때 여성 메시에는 `SKM_Player_Woman_Physics`가 연결되어 있었고 남성 메시에는 `PA_Mannequin`이 연결되어 있었다. 남성 체형의 래그돌 변형은 별도 확인한다.

## Physics Asset 조절과 현재 결정

2026-10-04 사용자는 전 부위 컨스트레인트의 회전 제한을 20도로 조절해 현재 캐릭터의 움직임이 자연스럽다고 확인했다. 이 값은 현재 아트 에셋의 튜닝 결과로 유지한다. 코드에서 전 관절을 20도로 덮어쓰거나 팔 바디를 추가하는 로직은 넣지 않는다. 다른 체형에도 같은 결과가 나오는지는 각각 확인해야 한다.

바디 간 충돌은 피부 메시가 아니라 Physics Asset의 캡슐/구체 등으로 계산한다. 바디가 너무 작거나 위치가 틀리면 회전 제한을 줄여도 관통이 남을 수 있다. 충돌 조절은 두 바디씩 선택해 한 쌍씩 적용한다. 여러 바디를 선택한 활성화는 선택 바디 사이의 모든 조합을 켜므로, 시작 자세에서 겹치는 이웃 바디끼리 서로 밀어내며 튈 수 있다. `pelvis ↔ thigh`, `thigh ↔ calf`처럼 직접 연결된 관절 주변의 충돌은 기본적으로 비활성화하고 관절 제한으로 접힘을 제어한다. `calf ↔ spine_04` 조합은 사용자가 안정적이라고 확인했다. 나머지 조합은 해당 에셋에서 확인한 결과에 맞춰 관리한다.

## 남은 제품 결정과 확인 사항

- 관전은 자신의 시체를 추적한다. 동료 관전 전환이나 수중 추락 시 카메라 제한은 별도 정책이 필요하다. 카메라 붐 이동은 시각 처리이며 게임플레이 캡슐 위치나 네트워크 거리 판정을 옮기지 않는다.
- 관절별 최종 래그돌 포즈는 각 피어의 물리 시뮬레이션 결과다. 모든 본의 포즈를 별도로 동기화하거나 시체를 이동 배에 고정하는 기능은 추가하지 않았다. 움직이는 갑판에서 지지·미끄러짐·서버/클라이언트 화면 차이를 확인한다.
- 대기 시체는 부활 지점이 복구될 때까지 유지한다. 무기한 대기에 대한 UI 안내·동료 관전·다른 부활 지점 사용 여부는 추후 결정한다. 부활 성공, 접속 종료, 전멸/레벨 종료에서는 현재 정리 경로를 사용한다.
- 짧은 간격으로 반복 사망하면 최소 30초 정책에 따라 시체가 여러 개 남을 수 있다. 시체 수 상한·안정화 후 물리 정지·사라짐 연출은 실제 성능과 아트 요구를 확인한 뒤 추가한다.
- 무기/부착물의 시체 충돌·드롭 여부, 물에 빠진 시체 처리, 관절별 회전 축과 제한은 아트/플레이 정책에 맞춰 검증한다. 20도 설정이 몸 관통이나 모든 무기 자세의 안정성을 보장하지는 않는다.
- 부활 시 PlayerState의 ASC는 새 Pawn으로 넘어간다. 기존 진행 상황 복구를 사용하며, 테스트 명령에 별도 인벤토리 초기화나 아이템 복제 경로를 만들지 않는다.

## 2026-10-04 자동 검증

커밋 전 최종 정리 후 직접 UBT의 Win64 Development Editor 빌드 성공. `PlayerDeathCommitFinal` 보고서에서 총 8개 테스트 성공(경고 포함 성공 1개), 실패 0. 기존 Vortex 부여 경고 2건은 `DevelopmentCommand`에 기록됐다.

- 카메라: 실제 여성 메시의 골반 물리 바디 이동 추적, 캡슐 위치·카메라 회전 유지, 중복 시작·본 누락·래그돌 해제 복구.
- GameMode: 중복 사망 등록, 부활 지점 미확보 시 보호·재시도, 지연 0 처리, 외부에서 완료된 새 Pawn 빙의 후 최소 수명·유예 적용, 대기 취소 시 타이머·시체 정리.
- 플레이어: 현재 소유 Pawn만 사망시키는 정책, 지속 ASC 체력/사망 태그 복구, 새 Pawn 빙의 후 카메라 복귀, 시체의 체력/상호작용 구독 해제, 늦은 시체 PlayerState 복제로 ASC Avatar를 빼앗거나 체력 구독을 재개하지 않는지 확인.
- 적 래그돌: 기존 방향·복제 계약·기본값·갑판 충돌 관련 5개 회귀 테스트.

실제 배의 스폰 성공이나 네트워크 RPC 순서는 재현하지 않으므로 호스트·게스트 PIE에서 별도로 확인한다. 사용자 확인 사항은 현재 캐릭터의 관절 제한 튜닝 결과이며 전체 네트워크/제품 시나리오 완료를 뜻하지 않는다. 보고서: `Saved/Automation/PlayerDeathCommitFinal/index.json`, 로그: `Saved/Logs/PlayerDeathCommitFinal.log`.
