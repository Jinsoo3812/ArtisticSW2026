# 플레이어 카메라 장애물 정책

> 현재 기본 플레이어 카메라는 사용자 요청에 따라 자동 충돌 당김을 끄고 수동 휠 줌으로 전환했다. 아래 내용은 충돌 회피를 명시적으로 켤 때 사용하는 선택 기능과 이전 검증 기록이다. 현재 기본 동작은 `Player_Manual_Camera_Zoom.md`를 따른다.

## 목적과 적용 범위

좁은 배 안에서 다른 플레이어·적·작은 구조물이 SpringArm을 과도하게 줄이는 문제를 카메라 쿼리에서 처리한다. 이동, 물리, 피격, 조준, 화살 채널의 응답이나 액터 가시성을 변경하지 않는다.

`ABasePlayer`의 기존 이름 `CameraBoom`과 `USpringArmComponent` 포인터 API를 유지하고, 네이티브 생성 클래스만 `USWCameraSpringArmComponent`로 변경했다. 걷기·수영의 구분으로 충돌을 켜고 끄지 않는다. 엔진의 회전/위치 lag, SocketOffset, ProbeChannel, ProbeSize와 충돌 보정 상태를 그대로 사용한다.

이 변경은 **카메라 장애물 정책의 구조 개선**이다. 실제 배의 통합 메시에는 아래의 카메라 전용 프록시를 적용했다. 기둥과 벽이 하나의 충돌 컴포넌트라면 컴포넌트 태그만으로 둘을 구분할 수 없으므로, 프록시를 생성해 카메라용 기하를 분리한다. 주관적인 조작감이나 모든 수명 주기의 무결성을 보증하는 변경은 아니다.

## 기본 동작

- 일반 `ACharacter`와 그 부착 장비/캐릭터 소유 장비는 카메라에서 무시한다. 원격 플레이어, 적, 캐릭터 액터가 유지되는 시체도 이 규칙을 따른다. 별도 액터로 생성된 시체·드롭 아이템은 자동 분류하지 않는다.
- `APawn` 전체를 무시하지 않는다. 배도 Pawn이므로 선체가 사라지는 부작용을 피한다.
- 벽·선체·지형·미분류 구조물은 기존 Camera 응답을 유지한다.
- 프로젝트 전역 프로필, 새 충돌 채널, 서버 RPC, 복제 상태 변경이 없다.
- 정책 추가 쿼리는 로컬 조종 Pawn에서 실행한다. 전용 서버와 원격 Pawn은 엔진 기본 경로를 사용한다. 별도 관전 시스템에서 원격 Pawn을 ViewTarget으로 쓰는 경우 이 정책은 적용되지 않으며 별도 연결이 필요하다.

## 구조물과 보스 지정

에디터의 일반 **Component Tags / Actor Tags**를 사용한다. Gameplay Tag 등록은 필요 없다.

| 태그 | 의미 |
| --- | --- |
| `SW.Camera.Ignore` | 카메라 검사를 통과시킨다. 이동·공격 판정에는 영향이 없다. |
| `SW.Camera.Block` | 자동 캐릭터 무시보다 우선하여 기존 Camera 차단을 유지한다. |

컴포넌트 태그가 액터/부착 계층 태그보다 우선한다. 같은 수준에서 Block과 Ignore가 함께 있으면 Block이 우선한다. 액터/부착 계층에서는 Block이 Ignore보다 우선한다. Block은 Camera를 원래 무시하는 컴포넌트를 새로 충돌체로 만들지는 않는다. 기본 Camera 채널에서 차단하는 충돌체만 쿼리 대상이다.

권장 저작 방법:

1. 독립된 작은 기둥·난간 컴포넌트에만 `SW.Camera.Ignore`를 지정한다.
2. 선체/벽/갑판이 섞인 배 액터나 통합 메시 전체에는 Ignore를 지정하지 않는다.
3. 거대 보스의 몸통을 카메라 장애물로 유지하려면 해당 컴포넌트 또는 보스 액터에 Block을 지정한다. 특정 부속품만 통과시킬 때에는 그 컴포넌트에 Ignore를 지정한다.
4. 동적 생성 구조물/아이템에도 동일한 태그 규칙을 적용한다. 이름이나 크기로 자동 추정하지 않는다.

## 쿼리와 비용

엔진의 첫 구형 sweep이 아무것도 맞히지 않으면 추가 작업이 없다. 충돌한 경우 엔진이 계산한 정확한 시작점 `PreviousArmOrigin`부터 동일 경로를 다시 검사한다. 무시 대상 컴포넌트만 쿼리에서 제외하고 반복하므로 그 뒤의 벽이나 같은 액터의 차단 컴포넌트를 계속 찾는다. 액터 전체를 무시 목록에 넣지 않는다.

추가 sweep은 기본 8회, 설정 가능 범위는 1~32회다. 한도에 도달하면 마지막 충돌 위치를 사용한다. 밀집 구간에서 카메라가 다시 당겨질 수 있지만 아직 검사하지 않은 벽을 넘어가지는 않는다. 전역 액터 탐색이나 매 프레임 머티리얼 갱신은 없다.

`CameraBoom > CameraCollision > Diagnostics`에서 마지막 차단 컴포넌트, 무시한 컴포넌트 수, 한도 도달 여부를 확인한다. 정책이 비활성화된 경로에서는 진단값을 비운다.

## 롤백과 기존 기능

`CameraBoom.bEnableObstaclePolicy = false`로 엔진 기본 충돌 동작으로 돌아간다. `bIgnoreCharacters = false`는 기본 캐릭터 무시만 끄며 명시적인 태그는 유지한다. 카메라 관련 태그는 이 컴포넌트 밖의 쿼리에는 영향을 주지 않는다.

기존 조준은 `PlayerBowAimResolver`에서 WeaponAim/ArrowObstacle을 별도로 조회하고 실제 화살 비행은 발사 소켓에서 장애물을 검사한다. 이 코드와 채널은 변경하지 않았다. 카메라가 기둥을 통과해 적이 보이더라도 공격이 통과하도록 바뀌지 않는다. 실제 BP/맵에서의 조준점 일치와 발사 동작은 후속 검증 대상이다.

이번 단계에는 투명화, 실루엣, 머티리얼 변경, 충돌 복귀 전용 보간을 넣지 않았다. 투명화는 플레이 체감 확인 후 필요할 때 화면별 구현으로 추가한다. 머티리얼과 숨김 상태를 공유하거나 숨은 적의 위치를 노출하지 않도록 별도로 설계해야 한다.

## 실제 배 적용 및 2인 PIE 검증 — 2026-10-30

`Lvl_CY`의 `BP_PlayerShip_Kelvin`을 조사한 결과 가는 선실 기둥 16개가 `DeckMesh_Simple`의 통합 메시 `SM_Ship_Simple_V2` 안에 있었다. `ShipVisualMesh`는 NoCollision이며, `DeckMesh_Complex`도 Camera를 차단한다. 배 액터 전체를 Ignore하지 않았다.

카메라용 `SM_PlayerShip_Camera`를 생성하고 Kelvin BP에 `CameraObstacleMesh`를 추가했다. 소스 70,838개 삼각형 중 명시적으로 검토한 기둥 16개(448개 삼각형)만 제외하여 70,390개를 유지했다. 프록시는 QueryOnly, Camera만 Block, 나머지 채널 Ignore, 비표시, 그림자/Overlap 비활성이다. 원본 `DeckMesh_Simple`에는 `SW.Camera.Ignore`만 추가했다. 원본 메시의 파일 SHA-256은 변경 전후 동일하며 이동·물리·화살 충돌 기하는 수정하지 않았다. `DeckMesh_Complex`와 기존 벽 차단 컴포넌트는 유지했다. 맵 파일은 저장하지 않았다.

이것은 공유된 이동/카메라 기하 문제에 대한 **베이크 프록시를 이용한 구조적 우회 방식**이다. 원본 배 형상이 바뀌면 다시 저작해야 한다. 원본 해시·기둥 경계·예상 제거 수가 `validation/Ship_Camera_Pillar_Selection.json`에 고정돼 있으며, 원본 변경 시 저작 도구는 중단한다. `Scripts/Editor/author_ship_camera_proxy.py`와 `USWShipCameraAuthoringLibrary`가 재현 경로다. 블루프린트 저장 후 기존 맵을 다시 로드해 이미 배치된 인스턴스에도 프록시 메시/QueryOnly 설정이 적용되는 것을 확인했다.

에셋까지 롤백하려면 Kelvin BP에서 `CameraObstacleMesh`를 제거하고 `DeckMesh_Simple`의 Ignore 태그를 제거한 뒤 컴파일·저장·맵 재로드한다. 카메라 컴포넌트의 정책 스위치를 끄는 것은 엔진의 무필터 쿼리로 돌아가는 것이며, 추가한 프록시 에셋/컴포넌트까지 제거하지는 않는다.

### 제한 및 남은 확인

카메라 비교는 실제 움직이는 배의 컴포넌트를 사용하되 캐릭터를 고정한 검사다. 수영 이동/잠수/상승은 실제 입력 경로를 사용했으며, 선실과 수역 사이의 테스트 준비에는 텔레포트를 사용했다. 따라서 갑판에서 연속적으로 뛰어내린 뒤 사다리로 승선하는 전체 동선 검증은 아니다. 패킷 지연/손실, 별도 프로세스/전용 서버, 재접속·관전·맵 전환·침몰 전체 수명 주기는 미검증이다. 보스 차단 태그는 구조와 단위 테스트만 검증했으며 실제 보스 에셋에는 변경하지 않았다.

선실 복귀의 클라이언트 표본 1건에서 카메라 거리가 일시적으로 0에 가까워졌다. 동일 복귀 위치를 재검사했을 때 기존 정책도 약 53~81cm로 가까워졌으며, 새 정책은 약 90~104cm에서 `CameraObstacleMesh`에 차단됐다. 벽과 큰 구조물의 충돌은 의도적으로 유지한다. 최초 0 표본의 정확한 접촉 면은 기록하지 못했으므로 지속적인 전환 버그 또는 완전한 해결로 단정하지 않는다. 근접 큰 구조물/텔레포트 직후 카메라 처리는 후속 체감 검토 항목으로 남긴다.

최초 Python `BuildFromStaticMeshDescriptions` 호출에서 새 프록시 렌더 리소스 수명 오류로 에디터가 종료됐다. 원본 BP는 백업과 해시가 같아 저장 전 상태였음을 확인했다. 로그는 `Saved/CameraValidation/AuthoringCrash.log`에 보존했다. 저작 경로를 원본 MeshDescription 복사 → 새 에셋의 정규 `Build` → 컴파일 완료 대기로 변경했고, 프록시 생성/저장/맵 재로드/실제 PIE 검사를 완료했다. 엔진 파일이나 캐시 삭제는 하지 않았다.
