# 누락 에셋 원인 조사와 실제 프로젝트 복구

`JYU_merge`의 ShipAI 통합 후 확인한 프로젝트 에셋·회귀 오류를 수정했다. 실제 소스와 `Content`에 적용했으며 별도 패키지를 설치할 필요가 없다. 이전 통합 보고서의 실패 항목은 아래 후속 검증으로 대체한다.

## 결과

- 활성 콘텐츠의 누락 하드 패키지 참조 **389 → 0**. 복구·변경 에셋 실제 로드 실패 0.
- 프로젝트 BP 463개를 포함한 총 627개 컴파일: **오류 0 / 로드 실패 0**. 사용하지 않는 서드파티 예제 BP의 경고 8건은 아래에 구분한다.
- 사망·시체·부활·배 AI·앵커·네트워크 물리·개발 입력 회귀 **62/62 통과**.
- 애니메이션 참조 정리 후 남녀 12단계 실제 모션 매칭 **3,119프레임**, 비정상 수치·75° 초과 변형 본 회전 급변 후보 0. 시작 idle의 짧은 준비 프레임과 기존 여성 IK 마커 배율은 기존 검증과 구분해 기록한다.
- 실제 `Lvl_CY` 에디터 로드·렌더 성공, 로드된 액터 787개. 게임 실행이나 맵 저장 없이 확인했다. 별도 테스트 맵에서 남녀 약 10초 자동 부활·F11 전환·ASC 새 생명 소유권 확인.

수치·원본 커밋·복구 방법은 [검증 JSON](validation/Asset_Recovery_20261101.json), 원시 자료·변경 전 사본은 `Saved/AssetRepair`에 있다. Git/LFS 필터나 외부 객체 저장소 설정은 변경하지 않았다.

## 원인과 처리

### 폴더 정리 후 남은 구형 경로

전체 Git 이력에서 초기 누락 경로 52개를 조사해 31개 원본을 찾았다. `455ca9f1`의 폴더 정리, `7f3b3676`의 아이템 폴더 이전, `d086ec8e`의 샘플 메시 정리 후 일부 참조가 남아 있었다.

원본이 있는 메시·옛 맵·외부 액터는 정확한 이전 커밋에서 복구하고 헤더·크기·해시를 대조했다. 1,319바이트의 옛 테스트 선체는 손상된 메시가 아니라 **리다이렉터**였다. 그 목적지까지 추적해 `a5d4c2bb`의 실제 약 4.8MB 메시를 복구했다. 옛 `Lvl_SJY`의 추가 누락 액터도 `db814bee`에서 복구했다.

현재 정식/Legacy 경로가 있는 구형 BP·재질은 구형 구현을 중복 복사하지 않고 표준 리다이렉터로 연결했다. BP는 에셋뿐 아니라 기존 클래스/CDO 참조가 현재 클래스로 해석되는지도 검사했다. 17개 역사적 경로 연결과 두 기본값 연결은 기록을 분리했다.

### ignore 규칙 때문에 다시 누락될 수 있는 데이터

`.gitignore`는 데모 맵에서 사용하는 메시 폴더와 모든 World Partition 외부 액터/오브젝트를 제외하고 있었다. 필요한 데모 메시 15개만 좁게 예외로 허용하고, 맵의 실제 저작 데이터인 외부 액터/오브젝트의 전역 ignore는 제거했다. 관련 없는 다른 로컬 파일을 일괄 추가하지 않았다.

### 이순신 애니메이션 바인딩

원래 메시·Idle/Walk/Run은 같은 스켈레톤을 쓰지만 구형 ABP와 블렌드스페이스의 연결은 null이었다. 속도 샘플은 0·150·500인데 축 최대값은 100이었다. 원래 스켈레톤을 연결하고 지원 API로 축을 500까지 확장했다. 기존 그래프 7개 노드 GUID, 애니메이션, 샘플 속도·재생 배율을 보존했다. 현재 NPC Sash 변형의 그래프나 운영 캐릭터는 대체하지 않았다.

### 배 AI의 두 실패

배 예측기는 실제 선체 메시가 없으면 유효하지 않다고 판단해 정지한다. 앵커 테스트의 기본 배에는 메시가 없었다. 또 이전 회피 테스트는 무조건 후진하고 복귀 중 보호를 끄는 옛 방식을 기대하고 있었다.

운영 항법을 우회하거나 안전 장치를 끄지 않았다. 테스트에 유효한 선체를 제공하고 실제로 나빠지는 충돌 경로를 확인한 뒤 안전 정지를 검사하도록 보완했다. 복귀 중 겹친 선체와의 충돌 보호도 유지함을 확인한다. 운영 배 AI·물리·GAS·부활 코드는 이 후속 복구에서 변경하지 않았다.

구형 `DeckNavigationComponent` import가 남은 배 BP 4개는 정상 컴파일/저장으로 정리했다. 그래프와 편집 가능한 기본값이 전후 동일함을 검사했으며 새 대체 컴포넌트를 억지로 삽입하지 않았다.

### 불완전하게 옮겨진 샘플의 선택적 참조

51개 애니메이션에는 현재 사용하지 않는 실험용 DB·누락된 샘플 노티파이의 import가 남아 있었다. 로드 시 이미 null이던 선택적 힌트를 그대로 유지하고 정상 재직렬화했다. 전후 로드된 모든 노티파이 메타데이터가 완전히 같음을 대조했으며 포즈·커브·노티파이·그래프를 작성하거나 제거하지 않았다. 실제 운영 MM DB에 새로운 샘플 DB를 끼워 넣지 않았다.

원본 Foley enum은 로컬 GASP 자료에서 정확한 파일로 복구했다. 상위 엔진으로 저장된 실험 스키마는 직접 복사하지 않았다. 독립 임시 5.8 프로젝트에서 설정을 읽어 5.7 형식으로 재작성·대조한 원본 복구 자료는 `SourceArt/AssetRecovery/UnusedStateMachine`에 보존한다. 원본 실험 상태머신의 완전한 도입과 운영 MM 오류 수정은 구분한다.

### 원본이 없는 맵과 데모 자료

`Level_JWJ`와 파티클 쇼케이스는 어느 확인한 커밋/로컬 원본에도 맵 파일이 없었다. 해당 맵의 외부 패키지 215개는 활성 하드·소프트·관리·검색 가능 참조가 없음을 증명한 뒤 바이트와 해시 그대로 `SourceArt/Legacy/OrphanWorlds`로 옮겼다. 이는 **구조적 보존/격리**이며 없어진 맵을 복구했다는 의미가 아니다. 이동 전 경로·해시는 보존 manifest와 Git rename에 남는다. 빈 맵으로 참조를 맞추지 않았다.

원본을 찾지 못한 데모용 매크로 텍스처와 구형 컬러웨이는 명시적인 엔진 표준 매크로 텍스처/현재 템플릿 기본 재질로 연결했다. 원본 그림을 되찾았다고 주장하지 않으며 두 경로와 목적지를 보고서에 기록한다. 원래부터 제외된 생성 조명 BuiltData의 오래된 import는 데모 맵을 정상 저장해 정리했다. 원래 베이크된 조명을 복구한 결과가 아니며 정적 조명을 다시 사용할 때는 재빌드가 필요하다.

## 10초 부활의 출처와 테스트 범위

모션 매칭 비교 스크립트가 매번 검증용 GameMode BP를 저장하던 것도 확인했다. 비교 실행에서 명시적 저장을 제거하고, 동일 설정이면 재컴파일하지 않으며 필요한 임시 컴파일에도 `SkipSave`를 사용한다. 원래 실행을 다시 수행해 해당 에셋 SHA-256이 전후 같음을 검사한다. 이는 파일을 사후 복원하는 방식 대신 불필요한 쓰기를 발생 지점에서 없앤 수정이다.

운영 `AMultiGameMode::IndividualRespawnDelay = 10.0f`는 **2026-09-30의 `97f323805`**부터 있던 정책이다. 사망 완료 후 운영 대기 시간·시체 수명·부활 타이머가 같은 값을 사용한다. 이 코드는 수정하지 않았다.

에디터 전용 테스트 맵은 입력 후 별도 타이머/새 생명 fixture로 부활한다. 운영 GameMode 전체를 재현하는 테스트라고 주장하지 않는다. 숫자는 같은 기존 상수를 참조해 중복 하드코딩을 없앴다. 운영의 방/배 스폰 조건·사망 완료 후 타이머는 별도 실제 MultiGameMode 생명주기 회귀로 검사한다.

- 테스트 맵: `/Game/Developers/PlayerRagdoll/L_PlayerRagdollTest`, 1인 Selected Viewport PIE.
- Ctrl+Alt+Shift+F10: 테스트 사망·자동 부활.
- Ctrl+Alt+Shift+F11: 남녀 전환.

## 남은 경고와 검증 한계

BP 오류는 0이지만 예제 `BP_VFX_Explosions`의 deprecated 함수 경고 1건과 `StylizedWeather/ThirdPersonCharacter`의 미등록 legacy 입력 경고 7건은 남긴다. 운영 Enhanced Input 설정을 예제 경고를 없애기 위해 전역 변경하지 않았다.

한국어 에디터에서 맵 로드 전 출력되던 일반 `Condition failed` 4건은 엔진의 `FStructuredLogFormatTest` 자체 검사였다. 동일 맵/실행을 한 번 `-culture=en`으로 대조하면 해당 검사가 통과하고 오류 로그가 없다. 프로젝트 콘텐츠 오류와 구분했으며 프로젝트 언어/엔진 설치 파일을 바꾸거나 테스트를 비활성화하지 않았다. 엔진 자체의 한국어 로그 테스트 문제까지 수정했다고 주장하지 않는다.

빌드·파일/LFS 무결성·활성 참조·BP 컴파일·실제 모션 매칭·시체/부활 회귀의 범위이며 cook/packaging, 장시간 네트워크 지연, 다수 시체 성능과 모든 LOD/모프/커스텀 재질 조합을 검증한 결과는 아니다.
