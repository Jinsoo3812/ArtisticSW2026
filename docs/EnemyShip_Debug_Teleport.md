# EnemyShip 플레이어 디버그 이동

플레이어는 기존 PlayerStart에서 정상적으로 생성하고, 빙의 및 적함 초기화가 완료된 뒤 콘솔로 적함에 이동한다. 직접 갑판에 스폰할 때 발생하는 문제를 분리해서 테스트하기 위한 기능이며, Enemy 이동 오류 자체를 수정하는 기능은 아니다.

## 에디터 설정

1. 레벨의 대상 EnemyShip 인스턴스에 **Actor Tags**로 `DebugShip01`을 추가한다. 같은 월드에서 유일해야 한다.
2. 해당 EnemyShip Blueprint의 **움직이는 갑판 메시 아래**에 Arrow 또는 Scene Component를 추가한다. 별도 월드 TargetPoint나 움직이지 않는 루트 아래에 두지 않는다.
3. 이 컴포넌트의 **Component Tags**에 `DebugArrival`을 추가한다. 컴포넌트 이름과 태그는 서로 다르다.
4. 도착 지점은 캐릭터 **캡슐 중심** 기준이다. 갑판 바닥에서 실제 플레이어의 scaled capsule half-height + 약 5~10cm 높이에 놓고 주변에 캡슐이 들어갈 공간을 확보한다. Arrow의 방향이 도착 후 바라볼 수평 방향이다.
5. Enemy 스폰 앵커와 겹치지 않는 별도 위치를 사용한다. 여러 위치를 쓰려면 `DebugArrivalBow`, `DebugArrivalStern` 등 서로 다른 컴포넌트 태그를 지정한다.

## 사용

싱글플레이, Listen Server 호스트 또는 **클라이언트 자신의 게임 창**에서 플레이어가 생성되고 대상 배가 활성화된 뒤 `~` 콘솔에 입력한다. 플레이어 컨트롤러는 프로젝트의 `BasePlayerController` 계열이어야 한다.

```text
SW.EnemyShip.Teleport DebugShip01 DebugArrival
```

실행 시점의 도착 컴포넌트 월드 좌표를 사용하므로 배의 이동과 회전을 반영한다. 충돌을 검사하는 TeleportTo가 성공하면 속도와 누적 힘을 지우고 낙하 상태로 전환한다. 이후 일반 착지 처리가 갑판 바닥을 찾고 이동 베이스를 설정한다. 캐릭터를 배에 강제 부착하지 않는다.

클라이언트는 자신의 PlayerController의 Reliable Server RPC로 두 태그만 전달한다. 서버가 요청한 컨트롤러의 현재 Pawn을 선택하고 적함과 도착 지점을 검색·검증하여 이동한다. 다른 플레이어, 월드 좌표 또는 대상 Actor를 클라이언트가 지정할 수 없다. 클라이언트에 해당 배가 아직 복제되지 않았더라도 태그 검색은 서버 월드에서 수행한다. 위치는 캐릭터의 서버 이동 보정/복제 경로를 사용하고, 시선은 소유 클라이언트에 별도로 전달한다.

명령은 Shipping/Test 빌드에서 제외되며 RPC 구현도 해당 빌드에서는 이동을 실행하지 않는다. 개발 빌드에서는 연결된 각 플레이어가 자기 캐릭터에 사용할 수 있다. 서버 요청은 컨트롤러당 0.25초 간격으로 제한한다. 로컬 플레이어가 여러 명인 경우, 사망·전환·상호작용 상태, 조타/대포에 부착되었거나 이동이 비활성화된 경우는 거부한다. 침몰·사망·스토리 비활성·거리 휴면 상태의 배도 거부한다. 거리 휴면 상태라면 먼저 배에 접근하여 활성화한다. 처리 결과는 요청한 클라이언트에 ClientMessage와 Output Log의 `LogSWEnemyShipDebugRequest`로 전달한다. 성공 로그는 서버의 `LogEnemyShipDebug`에도 남는다.

## PIE 검증

- 정상 PlayerStart에서 시작 → 명령 실행 → 지정 위치 도착 및 일반 이동 확인.
- 배가 이동/회전하는 중 반복 실행 → 도착 위치와 착지 후 갑판 추종 확인.
- 존재하지 않는 태그와 중복 태그 → 이동 없이 로그 출력 확인.
- 캡슐 공간이 없는 위치 → 순간이동 실패 및 기존 위치 유지 확인.
- Listen Server + 클라이언트 2인 PIE에서 클라이언트 창의 콘솔로 실행 → 클라이언트 캐릭터만 이동하고 호스트는 기존 위치를 유지하는지 확인.
- 호스트에서도 같은 명령 실행 → 호스트 캐릭터만 이동하는지 확인.
- 두 창에서 도착 위치와 도착 후 시선·일반 이동·갑판 추종 확인. 네트워크 지연을 적용한 상태에서도 되돌아감/지속적인 보정이 없는지 확인.
- 클라이언트에서 잘못된 태그 입력 → 클라이언트의 결과 메시지/로그 확인.

자동화 테스트 `ArtisticSW.Enemy.Ship.DebugTeleport.RequesterAndValidation`은 서버 처리 함수의 요청자 선택, 최신 도착 좌표, 속도 초기화 및 잘못된 대상 거부를 확인한다. 실제 네트워크 RPC 전송과 이동 보정은 위의 2인 PIE 검증 대상으로 남는다.
