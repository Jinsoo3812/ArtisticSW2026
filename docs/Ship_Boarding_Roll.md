# 바다 승선 후 C키 구르기 차단 수정

## 원인과 변경

바다의 수영 진입은 `State.Swimming` loose tag를 추가하며, 구르기는 이 태그가 있으면 발동하지 않는다. 플레이어 배와 적 배가 공유하는 `AShip::HandlePortSeaBoarding` / `HandleStarboardSeaBoarding`은 이동 모드를 바로 Walking으로 바꿔 순간이동한다. 기존 수영 종료 코드는 수영 모드일 때 수심 검사를 통과한 경로에서만 태그를 제거했다. 승선 후에는 이미 Walking이므로 그 분기에 들어가지 못해, 갑판에서 걷는데도 구르기 차단이 남았다. 선실 마스크나 이후 수영 재진입/이탈이 태그를 정리하면 회복돼 간헐적인 증상으로 보일 수 있었다.

`USwimmingComponent`가 소유 캐릭터의 `MovementModeChangedDelegate`를 구독한다. 프로젝트의 Custom Swimming 모드를 실제로 벗어나면 해당 컴포넌트가 즉시 수영 태그, 잠수/상승 입력, 수영 세부 상태와 물 조회 캐시를 정리한다. 서버뿐 아니라 예측/복제 이동 모드가 바뀌는 클라이언트에도 동일하게 적용된다. BeginPlay에서 연결하고 EndPlay에서 해제한다.

후속 [게임플레이 점검](Gameplay_Lifecycle_Audit.md)에서는 수영 태그도 소유권 헬퍼로 관리하도록 보강했다. 다른 기능이 같은 태그를 소유한 경우 그 카운트를 지우지 않는다. 최종 코드로 전체 자동 검사 89개와 같은 2인 승선 8개 사례를 다시 통과했다. 최종 증거는 `Saved/AudioIntegration/Live/7104/`와 후속 점검의 정량 보고서에 있다.

이것은 수영 모드와 GAS 상태가 어긋나는 원인을 수정한 것이다. 배별로 임시 태그 제거 코드를 넣거나, 구르기의 수영/피격 차단 조건을 완화하지 않는다. 실제 수영 중에는 기존처럼 구르기를 차단한다. 이동 모드 자체, 승선 위치, 판정 거리, 입력 매핑, 구르기 이동량과 무적 시간은 변경하지 않는다.

## 재현과 검증

- 수정 전/후 같은 2인 listen-server PIE에서 남녀를 사용했다.
- 두 소유 플레이어가 실제 물에 들어가 Custom Swimming과 수영 태그를 가진 상태인지 확인했다.
- 플레이어 배와 실제 `BP_EnemyShip`의 좌현/우현 승선 함수를 다음 게임 틱에서 호출했다.
- 적 배는 테스트 월드에 별도 생성했다. 맵의 비활성 풀 객체를 승선 대상으로 사용하지 않았다. 배 풀/활성화 로직의 검증은 포함하지 않는다.
- C 태그의 기존 InputAction에 Enhanced Input을 주입하고, 클라이언트와 서버의 구르기 능력 활성/태그 및 이동 모드를 기록했다. 물리 키보드 장치 입력 자체는 주입하지 않았다.
- 4회 반복 × 2명, 총 8개 승선 사례를 비교했다. 수정 전에는 6/8개에서 지상 이동 중 잔여 수영 태그가 관측됐다. 수정 후 8/8개에서 잔여 태그가 없었고 양쪽에서 C 입력 구르기가 활성화됐다.

원본 표본은 `Saved/AudioIntegration/Live/10820/`(수정 전), `Saved/AudioIntegration/Live/33412/`(수정 후)에 있다. 정량 요약은 [Ship_Boarding_Roll_20261031.json](validation/Ship_Boarding_Roll_20261031.json)이다. 빌드 로그는 `Saved/ShipBoardingValidation/After_Build.log`, 최종 검사 로그는 `Native_Final.log`다.

재현 진입점은 `Scripts/Editor/ShipBoardingValidation/verify_boarding.py`이며, 기존 `probe_world_audio.py` 명령 브리지의 `LiveScripts`에서 실행한다. 에디터 전용 `SWShipBoardingValidationLibrary`는 게임 틱에 승선/이동을 예약하고 GAS 상태를 읽는다. 실제 게임 모듈에 진단용 RPC나 입력 우회 경로를 추가하지 않는다.

새 회귀 검사는 외부 Walking/Falling/None 전환을 반복하며 수영 태그와 수직 입력 해제, 수영 중 구르기 차단, 피격 차단 유지 여부를 확인한다. 선실 수영 차단, 수영 네트워크 예측, 구르기 정책 검사도 함께 실행했으며 최종 7개 검사가 모두 통과했다. 최종 빌드도 성공했다. 가상 테스트 월드의 이동 컴포넌트를 명시적으로 초기화해 실제 이동 모드 변경 콜백이 실행되도록 한다.

전용 서버, 인위적인 고지연/패킷 손실, 모든 적 배 배치/풀 재활성화 경로는 이번 실행 범위에 포함하지 않는다.

수정 후 실제 PIE 결과와 설정 복원을 저장하고 에디터의 종료 로그/정상 종료 코드까지 확인했으나 마지막 종료 스레드가 남아 해당 테스트 PID만 종료 정리했다. 관련 프로세스 정보는 Saved에 보존했다. 이 정리를 엔진 종료 문제의 원인 수정으로 간주하지 않는다.
